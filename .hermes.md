# Hermes Agent — правила работы в проекте DataPath

## Основные правила

1. **Сначала изучить существующие файлы**, потом действовать.
2. **Выполнять работу небольшими проверяемыми этапами.** Не создавать большой монолит сразу.
3. **Всегда предлагать план** перед крупными изменениями.
4. **Не удалять файлы без явного подтверждения пользователя.**
5. **Не выполнять `git push`.**
6. **Не использовать `sudo`.**
7. **Не устанавливать глобальные зависимости.** Всё в venv или локально.
8. **Не переписывать весь vault без отдельного разрешения.**
9. **После изменений запускать подходящие проверки** (линтеры, тесты, type check).

## Канонический источник контента

10. **Единственный источник учебных материалов — `content/vault`** (Obsidian-хранилище).
11. Всегда использовать **относительный путь `content/vault`**.
12. Не использовать абсолютные пути конкретного компьютера.
13. Не создавать вторую копию учебных материалов.
14. Не использовать старое имя `My_brain_v2_DataPath`.

## Контент и RAG

15. RAG-индекс должен включать только материалы с `rag: include`.
16. Служебные файлы Obsidian (`.obsidian/`, `.git*`, `_meta/`) не должны попадать в RAG-индекс.
17. MOC, router, template, meta, daily notes, question bank — исключаются из RAG.
18. Изменения учебного контента выполняются непосредственно в `content/vault` через Obsidian или редактор кода.

## Технические ограничения

19. Целевая платформа: **MacBook Air M4, 16 ГБ unified memory**.
20. Архитектура должна учитывать доступную память.
21. Локальный RAG работает через **Ollama-совместимый API**.
22. Код должен быть понятным и поддерживаемым.
23. Документировать важные архитектурные решения в `docs/`.
24. Не переходить к следующему этапу без подтверждения пользователя.

## Честность

25. **Честно сообщать о неработающих или непроверенных частях.**
26. Не выдавать непроверенный код за работающий.
27. Не придумывать данные, если невозможно их получить.
28. Фиксировать открытые вопросы и компромиссы в `docs/decisions.md`.
