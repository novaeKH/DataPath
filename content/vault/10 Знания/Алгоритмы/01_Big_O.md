# 01. Big O

[[Python_Core_Шпаргалка|← Python Core]] · [[02_Array_String_Sorting|Следующий →]]

## 1. Цель урока

Оценивать рост времени и дополнительной памяти, находить доминирующую часть и не путать последовательные и вложенные циклы.

## 2. Главная идея

Big O отвечает не «сколько секунд», а «как растёт работа при росте размера входа n». Константы и младшие члены отбрасываются: `3n + 20` → O(n), `n² + n` → O(n²).

## 3. Как распознать

- один проход по n элементам → обычно O(n);
- вложенный полный проход n × n → O(n²);
- размер задачи делится пополам → O(log n);
- сортировка сравнениями → обычно O(n log n);
- перебор всех подмножеств → O(2ⁿ).

## 4. Когда правило «посчитать циклы» не работает

Смотрите, сколько раз тело выполняется суммарно. В Sliding Window два вложенно записанных указателя часто дают O(n), потому что каждый движется только вправо. Учитывайте стоимость операций внутри: `x in list` — O(n), `x in set` — O(1) в среднем.

## 5. Необходимый Python

Срез `items[a:b]` копирует k ссылок: O(k) времени и памяти. `sum(items)` — O(n). `list.sort()` — O(n log n). `len(list)` — O(1).

## 6. Универсальный шаблон оценки

1. Назвать размер входа.
2. Посчитать повторения дорогих операций.
3. Учесть скрытую стоимость методов и срезов.
4. Оставить доминирующий член.
5. Отдельно оценить дополнительную память, не считая вход и обычно результат.

## 7. Первая простая задача

```python
def contains_zero(values: list[int]) -> bool:
    for value in values:
        if value == 0:
            return True
    return False
```

Лучший случай O(1), худший и средний в обычной оценке O(n), память O(1). На интервью обычно называют худшую верхнюю границу и уточняют early return.

## 8. Вторая задача

```python
def pairs(values: list[int]) -> int:
    count = 0
    for left in range(len(values)):
        for right in range(left + 1, len(values)):
            count += values[left] != values[right]
    return count
```

Число пар `n(n-1)/2`, значит O(n²), память O(1).

## 9. Третья задача без решения

Оцените `while right < n` с внутренним `while left < right`, если `left` никогда не уменьшается. Почему это может быть O(n), а не O(n²)? Ответ — в [[Algorithms_Шпаргалка#Амортизированный анализ]].

## 10. Трассировка

| n | точное число пар | порядок |
|---:|---:|---|
| 4 | 6 | n² |
| 8 | 28 | n² |
| 16 | 120 | n² |

## 11. Инвариант

Для оценки двух монотонных указателей: каждый указатель прошёл не более n позиций.

## 12. Сложность

| Класс | Пример |
|---|---|
| O(1) | индекс list, `len` |
| O(log n) | Binary Search |
| O(n) | один проход |
| O(n log n) | сортировка |
| O(n²) | все пары |
| O(2ⁿ), O(n!) | полный перебор вариантов |

## 13. Типичные ошибки

- складывать последовательные циклы как O(n²);
- считать любой вложенный `while` квадратичным;
- забывать стоимость `in`, slice, `sum`, сортировки;
- говорить O(1) памяти при создании результата/копии;
- смешивать средний O(1) dict и гарантированный худший случай;
- оценивать по маленькому примеру.

## 14. Что сказать интервьюеру

> Пусть n — длина входа. Каждый элемент обрабатывается один раз, а операции внутри O(1), поэтому время O(n). Я храню только фиксированное число переменных, значит дополнительная память O(1). Если учитывать возвращаемый массив отдельно, его размер O(n), но он требуется контрактом.

## 15. Мини-контрольная

1. Два последовательных цикла по n?
2. Срез длины k?
3. Почему Binary Search O(log n)?
4. `x in list` внутри цикла по n?
5. Считают ли вход как дополнительную память?

<details><summary>Ответы</summary>
1. O(n). 2. O(k). 3. Пространство поиска делится пополам. 4. O(n²). 5. Обычно нет.
</details>

## 16. Практика

Обязательное: оценить все решения первых трёх уроков. Дополнительно: найти скрытые срезы. Повтор: через +1/+3/+7 объяснить один пример без кода.

## 17. Шпаргалка

Сначала размер входа → повторения → цена операции → доминирующий член → отдельно память.

## Где это встречается в Data Science

При выборе между Python-циклом, векторизацией, полным join и индексом; при оценке памяти батчей и матриц. Big O не заменяет benchmark и профилирование.
