# 04. Two Pointers

[[03_Hash_Map_и_Frequency_Map|← Предыдущий]] · [[05_Sliding_Window|Следующий →]]

## 1. Цель урока

Решать задачи встречными и slow/fast указателями, поддерживая чёткий обработанный префикс или диапазон.

## 2. Главная идея

Вместо проверки всех пар два индекса движутся по правилу, которое безопасно отбрасывает часть вариантов.

## 3. Как распознать

Сортированный массив, палиндром, симметричные элементы, in-place сжатие, удаление, слияние, linked-list cycle.

## 4. Когда не подходит

Неотсортированная Two Sum чаще требует Hash Map. Непрерывный диапазон с меняющимся состоянием — Sliding Window. Нельзя двигать указатель без доказательства, что отброшенные варианты не нужны.

## 5. Необходимый Python

`while left < right`, индексация, tuple-swap, `str.isalnum`, `str.casefold`.

## 6. Универсальные шаблоны

```python
left, right = 0, len(values) - 1
while left < right:
    # сравнить/обновить
    left += 1
    right -= 1
```

```python
write = 0
for read, value in enumerate(values):
    if should_keep(value):
        values[write] = value
        write += 1
```

## 7. Первая задача: LC 344 Reverse String

```python
def reverse_string(chars: list[str]) -> None:
    left, right = 0, len(chars) - 1
    while left < right:
        chars[left], chars[right] = chars[right], chars[left]
        left += 1
        right -= 1

chars = ["h", "i"]
reverse_string(chars)
assert chars == ["i", "h"]
```

Инвариант: элементы вне `[left, right]` уже стоят на зеркальных местах. Время O(n), память O(1).

## 8. Вторая задача: LC 125 Valid Palindrome

Пропускать неалфавитно-цифровые символы с обеих сторон, затем сравнивать `casefold()`. Важно два отдельных `while`, иначе можно сравнить символ, который тоже надо пропустить.

## 9. Третья задача без решения

LC 26 Remove Duplicates: [[02_Two_Pointers_задачи#LC 26 — Remove Duplicates from Sorted Array]]. Какую часть массива можно считать готовой?

## 10. Трассировка Reverse String

| left | right | до | после |
|---:|---:|---|---|
| 0 | 3 | `a b c d` | `d b c a` |
| 1 | 2 | `d b c a` | `d c b a` |

## 11. Инвариант

Встречные: всё вне интервала уже обработано. Slow/fast: `values[:write]` содержит ровно сохранённые элементы из просмотренного префикса.

## 12. Сложность

Обычно O(n) времени, O(1) памяти. Создание нормализованной строки или среза меняет память на O(n).

## 13. Типичные ошибки

- `right = len(values)`;
- неверное `left < right`/`<=`;
- забыть сдвинуть указатель на одной ветке;
- перезаписать ещё не прочитанный элемент;
- вернуть массив вместо требуемой длины;
- назвать O(1) при создании filtered string;
- применять к неотсортированной задаче без основания.

## 14. Что сказать интервьюеру

> Использую два указателя, потому что условие позволяет отбрасывать варианты после одного сравнения. Инвариант — всё вне текущего диапазона уже корректно. Каждый указатель проходит массив не более одного раза, поэтому O(n); храню только индексы — O(1).

## 15. Мини-контрольная

Когда slow/fast? Почему два указателя не O(n²)? Two Sum: map или pointers? Что возвращает LC 26? Какая граница у последнего индекса?

<details><summary>Ответы</summary>
Фильтрация/cycle; каждый монотонно проходит n; зависит от сортировки/памяти; длину уникального префикса; `len-1`.
</details>

## 16. Практика

Обязательные: 344, 125, 26, 27, 283, 167. Дополнительные: 88, 11. Повтор: 125 и 26.

## 17. Шпаргалка

Навстречу: `left=0,right=n-1`. Slow/fast: обработанный префикс `[:write]`. Всегда сформулируйте, почему движение безопасно.

## Где это встречается в Data Science

Слияние отсортированных временных рядов, in-place фильтрация буфера, сравнение нормализованных последовательностей. Реальная обработка часто в библиотеке, но инвариант тот же.
