## 1. Карта решений

| Симптом | Что проверить | Возможный метод |
|---|---|---|
| Большие значения target доминируют в ошибке | RMSE намного больше MAE, растёт разброс residual | log-target или robust loss |
| Важна относительная ошибка | бизнес оценивает ошибку в процентах | log-target, RMSLE/MAPE с оговорками |
| Есть реальные редкие экстремальные значения | строки корректны, но сильно влияют на модель | Huber/absolute/quantile loss |
| Есть подтверждённые ошибки данных | нарушены физические или бизнес-правила | исправление или заранее заданный фильтр |
| Модель недообучается | train и CV плохие | более гибкая модель, новые признаки |
| Модель переобучается | train сильно лучше CV | ограничение сложности, регуляризация |
| Модель уже хорошая, нужен небольшой прирост | стабильная CV и понятная метрика | ограниченный tuning |
| Нужно прогнозировать диапазон риска | важна неопределённость | quantile regression |

> [!important] Правило эксперимента
> Меняется одна идея, а исходная и новая версии сравниваются одинаковой CV по заранее выбранной основной метрике.

## 2. Подбор гиперпараметров

Tuning выполняется после сравнения семейств моделей. Обычно достаточно настроить 1–2 лучших кандидата.

```python
from sklearn.model_selection import RandomizedSearchCV

param_distributions = {
    "model__n_estimators": [100, 200, 300, 500],
    "model__learning_rate": [0.02, 0.05, 0.1],
    "model__max_depth": [2, 3, 4],
    "model__min_samples_leaf": [5, 10, 20, 30],
    "model__subsample": [0.6, 0.8, 1.0],
}

search = RandomizedSearchCV(
    estimator=gb_pipeline,
    param_distributions=param_distributions,
    n_iter=30,
    scoring=scoring,
    refit="rmse",
    cv=cv,
    return_train_score=True,
    random_state=42,
    n_jobs=-1,
)

search.fit(X_dev, y_dev)
```

Результат:

```python
print("Best parameters:", search.best_params_)
print("Best CV RMSE:", -search.best_score_)

best_pipeline = search.best_estimator_
```

Почему `-search.best_score_`: scoring `neg_root_mean_squared_error` хранится со знаком минус.

### Когда остановиться

- улучшение меньше разброса CV;
- новая модель намного сложнее ради очень малого прироста;
- результат нестабилен между фолдами;
- бюджет экспериментов исчерпан;
- улучшение не меняет бизнес-решение.

Не расширять поиск после просмотра final test.

## 3. Преобразование target

### Зачем

Логарифмирование сжимает большие значения:

```text
100 → log(101)
100 000 → log(100 001)
```

Модель начинает сильнее учитывать относительные различия и слабее — абсолютные ошибки дорогих объектов.

Это изменение задачи, а не автоматическое улучшение.

### Когда пробовать log1p

- target неотрицателен;
- распределение сильно скошено вправо;
- ошибка растёт вместе с уровнем target;
- бизнесу важнее относительная ошибка;
- несколько больших значений доминируют в MSE/RMSE.

### Безопасный sklearn-вариант

`TransformedTargetRegressor` обучает модель на `log1p(y)`, а predict автоматически возвращает исходный масштаб через `expm1`.

```python
import numpy as np

from sklearn.compose import TransformedTargetRegressor
from sklearn.linear_model import Ridge
from sklearn.pipeline import Pipeline

log_target_model = (
    TransformedTargetRegressor(
        regressor=Ridge(alpha=10),
        func=np.log1p,
        inverse_func=np.expm1,
    )
)

log_target_pipeline = Pipeline(steps=[
    (
        "preprocessor",
        clone(preprocessor),
    ),
    (
        "model",
        log_target_model,
    ),
])
```

Сравнить исходный и log-target одной CV:

```python
models_to_compare = {
    "Original target": original_pipeline,
    "Log target": log_target_pipeline,
}
```

Обычные `MAE`, `RMSE` и `R²` будут вычисляться в исходных единицах, потому что `predict()` выполняет обратное преобразование.

### Возможный результат

- MAE/MAPE улучшаются;
- ошибки становятся равномернее по диапазонам target;
- RMSE может ухудшиться, потому что дорогие промахи слабее влияют на обучение.

Если основная бизнес-метрика — RMSE в рублях, версия с log-target должна победить именно по RMSE в рублях.

### Ограничения

- `log1p` требует `y >= 0`;
- интерпретация коэффициентов меняется;
- после обратного преобразования может появиться bias;
- нельзя выбирать преобразование по final test.

## 4. Box–Cox и Yeo–Johnson

| Метод | Ограничение | Когда рассматривать |
|---|---|---|
| Box–Cox | только строго положительные значения | подобрать степенное преобразование положительного target |
| Yeo–Johnson | допускает ноль и отрицательные значения | target или признаки имеют сложную асимметрию |

Для признаков sklearn предоставляет:

```python
from sklearn.preprocessing import PowerTransformer

PowerTransformer(
    method="yeo-johnson",
    standardize=True,
)
```

Transformer должен находиться внутри Pipeline, чтобы параметр преобразования обучался отдельно на каждом фолде.

Для target требуется stateful-обёртка, которая обучает преобразование только на train-фолде и выполняет обратное преобразование predict. Не применять ручной `PowerTransformer().fit_transform(y)` до CV.

Для большинства рабочих baseline сначала достаточно сравнить исходный target и `log1p`.

## 5. Robust-модели и функции потерь

Robust loss уменьшает влияние крупных residual, если экстремальные объекты реальны и их нельзя удалять.

### Huber loss

Для градиентного бустинга:

```python
from sklearn.ensemble import GradientBoostingRegressor

robust_gb = GradientBoostingRegressor(
    loss="huber",
    n_estimators=300,
    learning_rate=0.03,
    max_depth=2,
    min_samples_leaf=10,
    random_state=42,
)
```

Huber ведёт себя квадратично для небольших residual и примерно линейно для крупных.

### Absolute error

```python
absolute_gb = GradientBoostingRegressor(
    loss="absolute_error",
    n_estimators=300,
    learning_rate=0.03,
    max_depth=2,
    min_samples_leaf=10,
    random_state=42,
)
```

Такая модель ближе к оптимизации медианного прогноза и MAE.

### Quantile regression

Прогноз 90-го процентиля:

```python
upper_model = GradientBoostingRegressor(
    loss="quantile",
    alpha=0.9,
    n_estimators=300,
    learning_rate=0.03,
    max_depth=2,
    min_samples_leaf=10,
    random_state=42,
)
```

Можно обучить нижний и верхний quantile для приблизительного диапазона прогноза. Это не готовый доверительный интервал: покрытие нужно проверять отдельно.

### Как выбирать loss

| Цель | Loss/метрика |
|---|---|
| минимизировать среднюю квадратичную ошибку | squared error / RMSE |
| минимизировать абсолютную ошибку | absolute error / MAE |
| компромисс и устойчивость | Huber |
| оценить верхний или нижний сценарий | quantile |

Loss обучения и основная бизнес-метрика могут различаться, но окончательное сравнение всегда выполняется по бизнес-метрике.

## 6. Работа с выбросами

Сначала определить, что именно обнаружено.

| Тип наблюдения | Действие |
|---|---|
| Ошибка ввода или измерения | исправить по источнику либо исключить по правилу качества |
| Значение невозможно по физике/бизнесу | применить документированное ограничение |
| Редкое, но реальное событие | обычно оставить; проверить robust method |
| Объект из другой генеральной совокупности | уточнить постановку и сегментацию |
| Большой residual без иной причины | не удалять автоматически |

### Безопасный процесс

1. Обнаружить подозрительное наблюдение только на development data.
2. Проверить исходные поля и источник.
3. Сформулировать правило независимо от ошибки модели.
4. Применять правило одинаково в будущих данных.
5. Сравнить исходный и изменённый подход одной CV.
6. Не выбирать правило по final test.

Пример физического правила:

```python
valid_mask = (
    X_dev["age"].between(18, 100)
    & y_dev.ge(0)
)

X_dev_clean = X_dev.loc[valid_mask].copy()
y_dev_clean = y_dev.loc[valid_mask].copy()
```

Здесь границы должны идти из смысла данных, а не из желания повысить метрику.

### Почему автоматическое IQR-удаление опасно

- хвост может быть основной бизнес-ценностью;
- для разных сегментов нормальные диапазоны отличаются;
- многомерный редкий объект не обязательно выброс по одному столбцу;
- production всё равно может содержать такие значения.

## 7. Winsorization и clipping

Ограничение экстремальных признаков:

```python
lower = X_train["amount"].quantile(0.01)
upper = X_train["amount"].quantile(0.99)

X_train["amount_clipped"] = (
    X_train["amount"].clip(lower, upper)
)

X_valid["amount_clipped"] = (
    X_valid["amount"].clip(lower, upper)
)
```

Границы вычисляются только на train-фолде. Для CV нужен собственный transformer внутри Pipeline.

Clipping полезен, если прибор имеет редкие сбои или бизнес допускает насыщение эффекта. Он опасен, если реальные большие значения важны.

Не обрезать target только ради красивой метрики без изменения постановки задачи.

## 8. Early stopping

Early stopping прекращает обучение, когда validation-метрика не улучшается заданное число итераций.

Идея:

```text
много максимальных итераций
+ validation set
+ patience
→ остановка на лучшей итерации
```

Для CatBoost:

```python
model.fit(
    X_train,
    y_train,
    cat_features=categorical_features,
    eval_set=(X_valid, y_valid),
    early_stopping_rounds=50,
    use_best_model=True,
)
```

Final test нельзя использовать как `eval_set`. При честной CV early stopping выполняется отдельно внутри каждого фолда, что требует ручного CV-цикла или специальной интеграции.

## 9. Feature engineering

Новые признаки создаются из знания процесса, а не случайным перебором.

Типовые идеи:

- сумма связанных величин;
- отношение с безопасной обработкой нуля;
- возраст объекта на момент события;
- время с последнего события;
- агрегаты только по прошлому;
- взаимодействие двух факторов;
- логарифм сильно скошенного числового признака;
- групповые признаки без target.

```python
df["total_area"] = (
    df["first_floor_area"]
    + df["second_floor_area"]
    + df["basement_area"]
)
```

Каждый признак проверяется на:

1. доступность в момент прогноза;
2. отсутствие target leakage;
3. возможность вычислить в production;
4. стабильный CV-прирост.

## 10. Что не относится к шаблону регрессии

Проверка статистических гипотез по p-value — отдельная задача математической статистики. Она может использовать тот же датасет, но не является обязательным шагом обучения регрессионной модели.

Нельзя автоматически считать, что:

- маленький p-value означает большой или полезный эффект;
- различие доказывает причинность;
- проверка десятков гипотез без поправки корректна;
- гипотеза, придуманная после просмотра результата, подтверждена тем же p-value без оговорок.

Эту тему лучше изучать отдельным блоком после закрепления основного ML-пайплайна.
