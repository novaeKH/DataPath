# Универсальная схема бинарной классификации

> [!summary] Главная формула
> **Split → Pipeline → CV → выбор модели → OOF-вероятности → выбор порога → fit на всех development data → test один раз → бизнес-интерпретация.**

Эта заметка — рабочий шаблон для задач бинарной классификации: дефолт клиента, отклик на предложение, мошенничество, отток, наличие заболевания и т. п.

---

## 0. Сначала сформулировать задачу

До написания кода ответить:

1. Что является одним объектом?
2. Что означает класс `1`?
3. В какой момент модель делает прогноз?
4. Какие признаки доступны в этот момент?
5. Какая ошибка дороже: `False Positive` или `False Negative`?
6. Есть ли ограничение по числу решений: например, можно позвонить только 100 клиентам?

> [!warning] Проверка доступности признаков
> Если признак появляется после момента прогноза, это утечка из будущего. Например, продолжительность звонка нельзя использовать, если модель выбирает клиентов до звонка.

---

## 1. Отделить финальный test

Все решения по модели, параметрам и порогу принимаются без просмотра test.

```python
from sklearn.model_selection import train_test_split

X_dev, X_test, y_dev, y_test = train_test_split(
    X,
    y,
    test_size=0.2,
    stratify=y,
    random_state=42,
)
```

### Выбор схемы разбиения

| Структура данных | Что использовать |
|---|---|
| Независимые строки, бинарный дисбаланс | `StratifiedKFold` |
| Несколько строк одного клиента/пациента | `GroupKFold` или `StratifiedGroupKFold` |
| Прогноз будущего по прошлому | временное разбиение или `TimeSeriesSplit` |

> [!danger] Нельзя
> Случайно перемешивать временные данные или помещать одного клиента одновременно в train и validation.

## 2. Собрать preprocessing внутри Pipeline

```python
from sklearn.compose import ColumnTransformer
from sklearn.impute import SimpleImputer
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler

numeric_pipeline = Pipeline(steps=[
    ("imputer", SimpleImputer(strategy="median")),
    ("scaler", StandardScaler()),
])

categorical_pipeline = Pipeline(steps=[
    ("imputer", SimpleImputer(strategy="most_frequent")),
    ("onehot", OneHotEncoder(handle_unknown="ignore")),
])

preprocessor = ColumnTransformer(transformers=[
    ("numeric", numeric_pipeline, numeric_features),
    ("categorical", categorical_pipeline, categorical_features),
])
```

Полный pipeline:

```python
from sklearn.linear_model import LogisticRegression

pipeline = Pipeline(steps=[
    ("preprocessor", preprocessor),
    ("model", LogisticRegression(max_iter=1000)),
])
```

### Почему preprocessing должен быть внутри Pipeline

Во время CV каждый фолд должен самостоятельно обучить:

- медианы;
- средние и стандартные отклонения;
- набор категорий OHE;
- саму модель.

Иначе информация из проверочного фолда попадёт в обучение.

---

## 3. Настроить кросс-валидацию

```python
from sklearn.model_selection import StratifiedKFold

cv = StratifiedKFold(
    n_splits=5,
    shuffle=True,
    random_state=42,
)
```

Для дисбалансной классификации удобно сравнивать модели по AP и ROC-AUC:

```python
scoring = {
    "ap": "average_precision",
    "roc_auc": "roc_auc",
}
```

`average_precision` — sklearn-метрика, суммирующая precision–recall качество. Её часто неформально называют PR-AUC, хотя способ вычисления отличается от трапецеидальной площади через `auc(recall, precision)`.

---

## 4. Сравнить модели на одинаковых фолдах

```python
import pandas as pd

from sklearn.base import clone
from sklearn.ensemble import RandomForestClassifier
from sklearn.linear_model import LogisticRegression
from sklearn.model_selection import cross_validate
from sklearn.tree import DecisionTreeClassifier

models = {
    "Logistic Regression": LogisticRegression(max_iter=1000),
    "Decision Tree": DecisionTreeClassifier(
        max_depth=5,
        min_samples_leaf=20,
        random_state=42,
    ),
    "Random Forest": RandomForestClassifier(
        n_estimators=300,
        max_depth=6,
        min_samples_leaf=10,
        random_state=42,
        n_jobs=-1,
    ),
}

comparison = []

for model_name, estimator in models.items():
    candidate = Pipeline(steps=[
        ("preprocessor", clone(preprocessor)),
        ("model", clone(estimator)),
    ])

    scores = cross_validate(
        estimator=candidate,
        X=X_dev,
        y=y_dev,
        cv=cv,
        scoring=scoring,
        return_train_score=True,
        n_jobs=-1,
    )

    comparison.append({
        "model": model_name,
        "train_ap_mean": scores["train_ap"].mean(),
        "cv_ap_mean": scores["test_ap"].mean(),
        "cv_ap_std": scores["test_ap"].std(),
        "cv_roc_auc_mean": scores["test_roc_auc"].mean(),
    })

comparison = pd.DataFrame(comparison)
comparison["overfit_gap"] = (
    comparison["train_ap_mean"]
    - comparison["cv_ap_mean"]
)

comparison = comparison.sort_values(
    "cv_ap_mean",
    ascending=False,
		)

display(comparison)
```

### Как выбирать модель

Смотреть одновременно на:

1. `cv_ap_mean` — среднее качество;
2. `cv_ap_std` — устойчивость между фолдами;
3. `overfit_gap` — разницу train и CV;
4. сложность, скорость и интерпретируемость;
5. бизнес-ценность реального улучшения.

> [!important] Не всегда побеждает максимальная метрика
> Если сложная модель лучше на `0.001`, но сильнее переобучается и хуже объясняется, разумнее выбрать простую модель.

### Быстрая интерпретация bias–variance

| Train | CV | Вывод |
|---|---|---|
| Плохо | Плохо | Недообучение, высокий bias |
| Отлично | Заметно хуже | Переобучение, высокий variance |
| Хорошо | Немного хуже | Нормальное обобщение |

Небольшой gap сам по себе не является целью: модель может одинаково плохо работать и на train, и на CV.

## 5. Зафиксировать модель и гиперпараметры

После CV выбрать одну конфигурацию. Например:

```python
final_pipeline = Pipeline(steps=[
    ("preprocessor", clone(preprocessor)),
    (
        "model",
        RandomForestClassifier(
            n_estimators=300,
            max_depth=6,
            min_samples_leaf=10,
            random_state=42,
            n_jobs=-1,
        ),
    ),
])
```

На этом этапе алгоритм и гиперпараметры больше не меняются по результатам test.

---

## 6. Получить OOF-вероятности

OOF-прогноз для объекта создаёт модель, которая не видела этот объект при обучении.

```python
from sklearn.model_selection import cross_val_predict

oof_proba = cross_val_predict(
    estimator=final_pipeline,
    X=X_dev,
    y=y_dev,
    cv=cv,
    method="predict_proba",
    n_jobs=-1,
)[:, 1]
```

OOF-вероятности используются для выбора порога без обращения к test.

---

## 7. Выбрать порог

### Вариант A: максимум F1

Использовать, если нет бизнес-стоимостей и precision/recall примерно одинаково важны.

```python
import numpy as np

from sklearn.metrics import precision_recall_curve

precision_values, recall_values, thresholds = (
    precision_recall_curve(y_dev, oof_proba)
)

f1_values = (
    2
    * precision_values[:-1]
    * recall_values[:-1]
    / (
        precision_values[:-1]
        + recall_values[:-1]
        + 1e-12
    )
)

best_index = np.argmax(f1_values)

best_threshold = thresholds[best_index]

print("Threshold:", best_threshold)
print("OOF precision:", precision_values[best_index])
print("OOF recall:", recall_values[best_index])
print("OOF F1:", f1_values[best_index])
```

У `precision_values` и `recall_values` на один элемент больше, чем у `thresholds`, поэтому используется `[:-1]`.

### График precision, recall и F1

```python
import matplotlib.pyplot as plt

plt.figure(figsize=(9, 5))

plt.plot(thresholds, precision_values[:-1], label="Precision")
plt.plot(thresholds, recall_values[:-1], label="Recall")
plt.plot(thresholds, f1_values, label="F1")

plt.axvline(
    best_threshold,
    color="black",
    linestyle="--",
    label=f"Threshold = {best_threshold:.3f}",
)

plt.xlabel("Threshold")
plt.ylabel("Metric")
plt.legend()
plt.grid(alpha=0.3)
plt.show()
```

### Как выбирать порог по задаче

| Задача | Способ выбора |
|---|---|
| Precision и recall одинаково важны | Максимум F1 |
| Опасно пропустить класс `1` | Recall, F2 или ограничение `recall ≥ X` |
| Ложное срабатывание дорого | Precision, F0.5 или ограничение `precision ≥ X` |
| Можно обработать только `K` объектов | Top-K вместо фиксированного порога |
| Известны стоимость ошибок и прибыль | Максимум ожидаемой прибыли |

> [!warning] Порог `0.5` не является универсальным
> Он лишь используется по умолчанию. При дисбалансе и разных стоимостях ошибок оптимальный рабочий порог часто другой.

## 8. Обучить финальную модель на всех development data

```python
final_pipeline.fit(X_dev, y_dev)
```

CV-модели были временными. Теперь создаётся одна модель, использующая все доступные development data.

## 9. Один раз оценить test

```python
from sklearn.metrics import (
    average_precision_score,
    confusion_matrix,
    f1_score,
    precision_score,
    recall_score,
    roc_auc_score,
)

test_proba = final_pipeline.predict_proba(X_test)[:, 1]

test_pred = (
    test_proba >= best_threshold
).astype(int)

print("AP:", average_precision_score(y_test, test_proba))
print("ROC-AUC:", roc_auc_score(y_test, test_proba))
print("Precision:", precision_score(y_test, test_pred))
print("Recall:", recall_score(y_test, test_pred))
print("F1:", f1_score(y_test, test_pred))
print("Confusion matrix:\n", confusion_matrix(y_test, test_pred))
```

### С чем сравнивать AP

Простой ориентир для AP — доля положительного класса:

```python
ap_baseline = y_test.mean()
```

Например, `AP = 0.42` при baseline `0.11` означает, что ранжирование значительно лучше случайного.

## 10. Перевести результат в бизнес

Техническая метрика не отвечает на вопрос, что получит компания.

### Пример Top-K

```python
results = pd.DataFrame({
    "actual": y_test.to_numpy(),
    "score": test_proba,
})

k = 100
selected = results.nlargest(k, "score")

precision_at_k = selected["actual"].mean()
recall_at_k = selected["actual"].sum() / results["actual"].sum()
lift_at_k = precision_at_k / results["actual"].mean()

print("Precision@K:", precision_at_k)
print("Recall@K:", recall_at_k)
print("Lift@K:", lift_at_k)
```

### Шаблон объяснения результата

> Модель ранжирует объекты с `CV AP = ... ± ...`. На нетронутом test получено `AP = ...` при baseline `...`. При обработке верхних `K` объектов модель находит `...%` положительных случаев и увеличивает эффективность относительно случайного выбора в `...` раза.

## 11. Интерпретация модели

Для model-agnostic оценки можно использовать permutation importance:

```python
from sklearn.inspection import permutation_importance

importance = permutation_importance(
    estimator=final_pipeline,
    X=X_test,
    y=y_test,
    scoring="average_precision",
    n_repeats=10,
    random_state=42,
    n_jobs=-1,
)

importance_df = pd.DataFrame({
    "feature": X_test.columns,
    "importance_mean": importance.importances_mean,
    "importance_std": importance.importances_std,
}).sort_values("importance_mean", ascending=False)

display(importance_df.head(10))
```

Помнить:

- важность не доказывает причинность;
- коррелирующие признаки могут заменять друг друга;
- большой `importance_std` означает нестабильную оценку;
- интерпретацию нужно проверять на бизнес-смысл и возможную утечку.

## 12. Типовые ошибки

- Обработать весь датасет до split.
- Выбирать модель или порог по test.
- Использовать случайный CV для временных или групповых данных.
- Сравнивать модели на разных фолдах.
- Считать AP/ROC-AUC по результату `predict()` вместо вероятностей.
- Считать accuracy основной метрикой при сильном дисбалансе.
- Считать порог `0.5` универсальным.
- Выбирать модель только по train-метрике.
- Считать маленький overfit gap гарантией хорошей модели.
- Использовать признак, которого не будет в момент реального прогноза.
- Делать вывод о сегменте по нескольким объектам.
- Считать feature importance доказательством причинности.

## Формула для собеседования

> Сначала отделяю нетронутый test с учётом структуры данных. Все преобразования помещаю внутрь Pipeline. На development data одинаковой CV сравниваю модели и гиперпараметры по порогонезависимой метрике. Для выбранной конфигурации получаю OOF-вероятности и выбираю порог по бизнес-стоимости ошибок, ограничению или F1. Затем обучаю одну модель на всех development data и один раз оцениваю test техническими и бизнес-метриками.
