# Дополнительные DL-задачи

Эта заметка помогает правильно определить задачу. Она не заменяет отдельный production pipeline.

## Segmentation

| Вариант | Logits | Target | Loss |
|---|---|---|---|
| Binary mask | `[B,1,H,W]` | `[B,1,H,W]` float | BCE + Dice |
| Multiclass mask | `[B,C,H,W]` | `[B,H,W]` long | CE + Dice |

Метрики: Dice, IoU per class. Split — по объекту/пациенту/сцене, не по отдельным tiles.

## Seq2Seq

```text
encoder input       [B,S]
decoder input       [B,T]
decoder logits      [B,T,V]
labels              [B,T]
loss                token CE, padding=-100
```

Нужны:

- encoder attention mask;
- decoder causal mask;
- teacher forcing на train;
- autoregressive decoding на inference;
- task-specific метрика: BLEU/ROUGE плюс human eval.

## Time series forecasting

```text
history window [B,T,F]
forecast       [B,H,K]
```

Обязателен chronological split и walk-forward evaluation. Нельзя перемешивать будущее в train. Baseline: last value, seasonal naive, классическая модель.

## Object detection

Target имеет переменное число объектов:

```text
boxes  [N,4]
labels [N]
```

Обычно используются готовые framework pipelines, несколько loss и mAP по IoU thresholds. Обычный classification loop недостаточен.

## Diffusion

Модель предсказывает noise/velocity на случайном timestep. Train и sampling — разные процедуры. Нужен отдельный scheduler шума и итеративная генерация.

## GAN

Два оптимизатора и две конкурирующие модели: generator и discriminator. Нельзя вставить GAN в обычный один-loss loop без изменения логики.

## Reinforcement learning

Target не является фиксированной меткой из датасета. Данные зависят от policy, а цель строится через reward/return. Нужен отдельный RL pipeline.

## Правило

Если target или процесс получения данных не помещается в таблицу [[10 Знания/ML/02 Deep Learning/01 База/02 - Формы dtype logits loss]], сначала создай отдельный паспорт и специализированную схему, а не копируй ближайший шаблон.
