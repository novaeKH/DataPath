# Утечки и проверка DL-данных

## Четыре вида утечки

1. **Target leakage** — признак появился после события или прямо кодирует target.
2. **Split leakage** — связанные объекты есть в разных частях.
3. **Preprocessing leakage** — статистики обучены до split.
4. **Selection leakage** — test используется для выбора решения.

## Типовые утечки по данным

| Данные | Что группировать |
|---|---|
| Банковские транзакции | client/account |
| Диалоги | conversation_id |
| Документы/chunks | document_id |
| Изображения | patient/object/series/video |
| Временные события | время + сущность |
| Истории для LM | story/source/template |
| Query-document | query family и при необходимости document family |

## Проверка пересечения id

```python
train_ids = set(train_group_ids)
valid_ids = set(valid_group_ids)
test_ids = set(test_group_ids)

assert train_ids.isdisjoint(valid_ids)
assert train_ids.isdisjoint(test_ids)
assert valid_ids.isdisjoint(test_ids)
```

## Проверка exact duplicates

```python
def normalized_text(text):
    return " ".join(text.lower().split())


train_text_set = {
    normalized_text(text)
    for text in train_texts
}

valid_text_set = {
    normalized_text(text)
    for text in valid_texts
}

overlap = train_text_set & valid_text_set
print("Exact overlap:", len(overlap))
```

Для near-duplicates нужны hashes по нормализованным объектам, similarity или perceptual hashes для изображений.

## Проверка времени

```python
assert train_dates.max() < valid_dates.min()
assert valid_dates.max() < test_dates.min()
```

Если окна пересекаются, проверь, не использует ли feature будущую информацию.

## Проверка preprocessing

Правильно:

```python
scaler.fit(X_train)
X_train_scaled = scaler.transform(X_train)
X_valid_scaled = scaler.transform(X_valid)
X_test_scaled = scaler.transform(X_test)
```

Неправильно:

```python
X_scaled = scaler.fit_transform(X)
# split после fit
```

## Проверка подозрительно хорошей метрики

1. Удали самые сильные признаки по одному.
2. Проверь качество простого baseline.
3. Перемешай labels: качество должно упасть к случайному уровню.
4. Проверь top confident errors вручную.
5. Пересобери group/time split.
6. Проверь, не попал ли target в имя файла, prompt, metadata или sequence.

## Label-shuffle test

```python
rng = np.random.default_rng(42)
shuffled_y = rng.permutation(y_train)
```

Если модель остаётся очень хорошей на случайных labels, почти наверняка есть утечка или ошибка оценки.

## Финальный контроль

- [ ] split отражает production;
- [ ] preprocessing fit только на train;
- [ ] дубликаты и группы проверены;
- [ ] test не участвовал в выборе;
- [ ] метрики считаются на уровне реального объекта/запроса;
- [ ] ручная проверка ошибок не противоречит метрике.
