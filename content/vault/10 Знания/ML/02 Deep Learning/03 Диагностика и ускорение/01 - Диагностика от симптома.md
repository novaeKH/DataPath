# Диагностика DL от симптома

> [!summary] Первый тест
> Попробуй переобучить модель на одном маленьком батче. Если loss не падает почти до нуля у достаточно гибкой модели, сначала ищи ошибку в коде или данных.

## Быстрая карта

| Симптом | Сначала проверить |
|---|---|
| Loss не меняется | `step`, `requires_grad`, lr, labels, shapes |
| Loss `NaN/inf` | данные, lr, деление на ноль, AMP, logits |
| Train падает, valid растёт | переобучение, split, регуляризация |
| Train и valid оба плохие | underfitting, признаки, lr, capacity |
| Valid слишком хороший | leakage, duplicates, group/time split |
| Метрика плохая, loss падает | неверная метрика/threshold/дисбаланс |
| Каждый запуск сильно разный | seed, маленький valid, nondeterminism |
| CUDA OOM | [[10 Знания/ML/02 Deep Learning/03 Диагностика и ускорение/03 - CUDA OOM и ускорение]] |

## 1. Проверить один batch

```python
batch = next(iter(train_loader))

if isinstance(batch, dict):
    for key, value in batch.items():
        print(key, value.shape, value.dtype, value.device)
else:
    for value in batch:
        print(value.shape, value.dtype, value.device)
```

Ответь:

- target действительно соответствует входу?
- формы совпадают с [[10 Знания/ML/02 Deep Learning/01 База/02 - Формы dtype logits loss]]?
- labels находятся в допустимом диапазоне?
- в данных нет `NaN/inf`?
- mask не состоит из одних нулей?

## 2. Проверить forward

```python
model.eval()
with torch.inference_mode():
    logits = model(features.to(device))

print(logits.shape)
print(torch.isfinite(logits).all())
print(logits.min().item(), logits.max().item())
```

## 3. Проверить gradients

```python
optimizer.zero_grad(set_to_none=True)
loss.backward()

for name, parameter in model.named_parameters():
    if parameter.requires_grad:
        grad_status = (
            None
            if parameter.grad is None
            else parameter.grad.norm().item()
        )
        print(name, grad_status)
```

Если у всех обучаемых параметров `grad=None`, вычислительный граф разорван или параметры не участвуют в loss.

## 4. Переобучить один batch

```python
small_batch = next(iter(train_loader))
model.train()

for step in range(300):
    optimizer.zero_grad(set_to_none=True)
    loss, _ = task_step(model, small_batch, device)
    loss.backward()
    optimizer.step()

    if step % 25 == 0:
        print(step, loss.item())
```

Если loss не падает:

1. проверь target и loss;
2. убери Dropout/аугментации;
3. попробуй простой optimizer и разумный lr;
4. увеличь capacity;
5. проверь, что labels не случайны.

## 5. Как читать train/valid

| Train | Valid | Вывод |
|---|---|---|
| падает | падает | обучение работает |
| падает | растёт | overfitting |
| стоит | стоит | underfitting или ошибка |
| скачет | скачет | lr/batch/градиенты/данные |
| намного хуже valid | valid лучше | train augmentation/Dropout или подозрительный split |

## 6. Если loss падает, а метрика нет

- threshold не подходит;
- Accuracy скрывает дисбаланс;
- оптимизируется surrogate loss, не бизнес-метрика;
- class mapping перепутан;
- padding/ignored labels включены в метрику;
- regression metric считается не в исходном масштабе.
