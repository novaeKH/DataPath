# Итераторы и генераторы: данные по одному элементу

Файл с событиями может быть больше свободной памяти. Чтобы посчитать число покупок, не обязательно сначала прочитать все события в список. Достаточно получить одну строку, обработать её и перейти к следующей. Такой способ работы называется ленивым: значение вычисляется тогда, когда понадобилось.

Ленивость не гарантирует ускорение. Она меняет время выполнения работы и объём одновременно хранимых данных. Поэтому нужно понимать, кто запрашивает следующий элемент и какое состояние сохраняется между запросами.

## Коллекция и проход по коллекции

Итерируемый объект позволяет начать обход через `iter`. Список можно обходить многократно. Итератор хранит состояние конкретного прохода и выдаёт значения через `next`.

```python
items = [10, 20, 30]
cursor = iter(items)
print(next(cursor))   # 10
print(next(cursor))   # 20
print(list(cursor))   # [30]
print(list(cursor))   # []
print(list(items))    # [10, 20, 30]
```

Итератор дошёл до конца. Повторное преобразование в список не вернуло данные, потому что проход уже исчерпан. Исходный список не исчез: из него можно получить новый итератор.

Цикл `for` скрывает этот механизм. Он получает итератор, запрашивает очередной элемент и завершает обход при сигнале `StopIteration`. Поэтому один цикл работает со списком, файлом и генератором, хотя эти объекты хранят данные по-разному.

## Генератор приостанавливает функцию

Обычная функция возвращает результат через `return`. Генераторная функция использует `yield`: выдаёт значение и приостанавливается, сохраняя локальные переменные.

```python
def squares(limit):
    for number in range(limit):
        print("Вычисляем", number)
        yield number * number

stream = squares(3)
print("Генератор создан")
print(next(stream))
print(next(stream))
```

Сначала появится «Генератор создан». Затем «Вычисляем 0» и `0`, потом «Вычисляем 1» и `1`. При создании `stream` тело ещё не выполнялось. Каждый `next` продолжает вычисление до следующего `yield`.

`range(3)` описывает числа 0, 1, 2 без создания списка всех чисел. Это итерируемая последовательность, а не одноразовый генератор: её можно обходить заново. Не всякий экономный объект является итератором.

## Собираем поток преобразований

Пусть события представлены словарями. Мы хотим посчитать сумму покупок, игнорируя просмотры:

```python
events = [
    {"kind": "view", "amount": 0},
    {"kind": "purchase", "amount": 100},
    {"kind": "purchase", "amount": 50},
]

def purchase_amounts(rows):
    for row in rows:
        if row["kind"] == "purchase":
            yield row["amount"]

print(sum(purchase_amounts(events)))   # 150
```

Первое событие проходит проверку, но не выдаёт значения. Второе выдаёт 100, третье — 50. Функция `sum` потребляет значения и хранит накопленную сумму. Промежуточного списка сумм не возникает.

Для файла та же идея выглядит так:

```python
from pathlib import Path

def nonempty_lines(path):
    with Path(path).open(encoding="utf-8") as source:
        for line in source:
            cleaned = line.strip()
            if cleaned:
                yield cleaned
```

Здесь аргумент — путь к вашему текстовому файлу, а результат — источник непустых строк. Блок `with` держит файл открытым во время чтения и закрывает при выходе из блока. Если вызывающий код прерывает потребление генератора, важно также управлять временем его жизни: удобство ленивости не отменяет управление ресурсом.

## Полезные инструменты обхода

`enumerate` добавляет счётчик к элементам, а `zip` объединяет несколько потоков по позициям:

```python
names = ["Анна", "Борис"]
scores = [8, 10]
for position, (name, score) in enumerate(zip(names, scores, strict=True), start=1):
    print(position, name, score)
# 1 Анна 8
# 2 Борис 10
```

По умолчанию `zip` останавливается по самому короткому источнику. Если разная длина означает потерю данных, `strict=True` позволяет обнаружить ошибку.

`yield from` передаёт наружу значения вложенного источника. `itertools.chain` последовательно объединяет источники, а `islice` берёт ограниченный фрагмент, не превращая весь поток в список:

```python
from itertools import chain, islice

stream = chain([1, 2], [3, 4])
print(list(islice(stream, 3)))   # [1, 2, 3]
print(list(stream))             # [4]
```

Обратите внимание: первый вывод уже продвинул исходный итератор.

## Когда материализация нужна

Если данные нужно сортировать, несколько раз обходить или получать произвольный элемент по индексу, список может оказаться правильным решением. `list(generator)` явно материализует поток — вычисляет и сохраняет все значения.

Экономия памяти исчезает, если ленивый источник сразу превращается в огромный список. Генератор также может сам удерживать крупные объекты в локальных переменных. Поэтому оценивайте всю цепочку, а не наличие одного `yield`.

## Самопроверка и практика

1. Почему второй `sum` над тем же генератором может вернуть ноль?
2. В какой момент возникнет ошибка внутри генераторной функции?
3. Почему `range` можно обойти повторно?
4. Что произойдёт с лишними метками при обычном `zip`?

Разбор: источник исчерпан; ошибка возникает при выполнении соответствующего шага, обычно во время потребления; `range` создаёт новый итератор для нового прохода; обычный `zip` молча остановится раньше.

**Практика.** Напишите генератор положительных чисел из `[3, -1, 0, 5]`. Первый обход должен дать `[3, 5]`, второй обход того же генератора — `[]`. Создайте новый генератор и получите сумму 8. Поясните, какие объекты хранят данные, а какие — только состояние обхода.

В визуализации проходите `next` по шагам и наблюдайте локальные переменные. Для интервью главное различие: итерируемый объект позволяет начать обход, итератор представляет уже начатый проход.
