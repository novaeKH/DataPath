# Функции: понятный вход, результат и состояние

Представьте, что скидка считается в пяти местах программы. Если правило изменится, придётся найти и исправить каждую копию. Функция позволяет один раз назвать правило и вызывать его с разными данными. Хорошая функция также делает понятным, что она получает, что возвращает и что изменяет снаружи.

## От выражения к функции

Начнём с цены после скидки. Параметры — имена во время определения функции; аргументы — значения при конкретном вызове. `return` возвращает результат и завершает текущий вызов.

```python
def discounted_price(price, rate=0.1):
    return price * (1 - rate)

print(discounted_price(200))             # 180.0
print(discounted_price(200, rate=0.25))   # 150.0
```

В первом вызове `price` равен 200, а `rate` получает значение по умолчанию 0.1. Вычисление идёт как `200 * 0.9`. Во втором вызове переданная ставка заменяет значение по умолчанию.

`print` и `return` решают разные задачи. Напечатанное число видно человеку, но другая функция не получает его автоматически. Без `return` функция возвращает `None`. Поэтому вычисления обычно возвращают данные, а вывод оформляют отдельно.

## Как сделать вызов однозначным

Аргументы можно передавать по позиции или по имени. Для нескольких похожих чисел именованный вызов легче читать. Символ `*` в определении делает следующие параметры только именованными:

```python
def final_price(price, *, discount=0.0, delivery=0.0):
    return price * (1 - discount) + delivery

print(final_price(200, discount=0.25, delivery=20))   # 170.0
```

Ограничение помогает не перепутать скидку и доставку. Символ `/`, напротив, обозначает параметры, которые передают только по позиции; при знакомстве с библиотекой его можно встретить в документации.

`*args` собирает дополнительные позиционные аргументы в кортеж, `**kwargs` — именованные в словарь. При вызове звёздочки выполняют обратное действие: распаковывают коллекцию аргументов. Это удобно для обёрток, но у основной бизнес-функции явные параметры обычно понятнее.

## Где функция ищет имена

У каждого вызова есть локальная область видимости. Если имя не найдено в ней, Python ищет его во внешних функциях, модуле и встроенных именах. Этот порядок называют LEGB.

```python
rate = 0.1

def calculate(price):
    rate = 0.2
    return price * (1 - rate)

print(calculate(100))   # 80.0
print(rate)             # 0.1
```

Локальное присваивание не изменило переменную модуля. `global` и `nonlocal` позволяют явно менять внешнюю привязку, но скрытое общее состояние усложняет понимание программы. Передать значение аргументом и вернуть новое значение часто проще.

Функция тоже является объектом: её можно передать в другую функцию или вернуть как результат. Замыкание — функция, использующая окружение своего определения:

```python
def make_scaler(factor):
    def scale(value):
        return value * factor
    return scale

double = make_scaler(2)
triple = make_scaler(3)
print(double(5), triple(5))   # 10 15
```

Каждый вызов `make_scaler` создаёт своё окружение. Внутренняя функция сохраняет доступ к соответствующему `factor` даже после завершения внешнего вызова.

## Почему отложенное выполнение иногда удивляет

Замыкания обычно обращаются к значению внешней переменной в момент вызова, а не сохраняют его отдельную копию в момент определения. Поэтому функции, созданные в одном цикле, могут видеть последнее значение переменной цикла.

```python
functions = [lambda: i for i in range(3)]
print([fn() for fn in functions])   # [2, 2, 2]

fixed = [lambda i=i: i for i in range(3)]
print([fn() for fn in fixed])       # [0, 1, 2]
```

`lambda` — краткая запись функции из одного выражения. Во втором случае значение фиксируется через параметр по умолчанию при создании каждой функции. Для сложной логики предпочитайте обычный `def`: имя и несколько строк объясняют намерение лучше.

## Декоратор как прозрачная обёртка

Декоратор принимает функцию и возвращает функцию с дополнительным поведением. Например, можно проверить вход, сохранив основное вычисление отдельно:

```python
from functools import wraps

def nonnegative_input(fn):
    @wraps(fn)
    def wrapped(value):
        if value < 0:
            raise ValueError("Ожидается неотрицательное число")
        return fn(value)
    return wrapped

@nonnegative_input
def square(value):
    return value * value

print(square(3))   # 9
```

Запись с `@` эквивалентна `square = nonnegative_input(square)`. `wraps` сохраняет имя и документацию исходной функции. Исключение `ValueError` сигнализирует о недопустимом значении; подробно обработаем его в уроке о надёжном Python. Декоратор с параметрами добавляет ещё один внешний вызов, создающий настроенную обёртку.

## Самопроверка и практика

1. Почему функцию, которая только печатает сумму, неудобно включать в расчёт среднего?
2. Почему локальный `rate` не меняет переменную модуля?
3. Чем замыкание отличается от обязательного копирования внешнего значения?
4. Когда декоратор оправдан?

Разбор: вычислению нужен возвращаемый результат; области видимости различаются; замыкание сохраняет доступ к окружению; декоратор полезен для повторяющегося поведения вокруг разных функций, например измерения времени, а не ради усложнения одного вызова.

**Практика.** Напишите `make_discount(rate)`, возвращающую функцию расчёта цены. Для ставки 0.2 цена 250 должна превратиться в 200. Проверьте две независимо созданные скидки. Объясните, где хранится ставка и почему вызовы не должны менять глобальную переменную.

Старайтесь делать вычислительные функции чистыми: одинаковый вход даёт одинаковый результат без изменения внешних объектов. Это упрощает будущие тесты и обработку данных. В следующем уроке научимся выдавать результаты постепенно.
