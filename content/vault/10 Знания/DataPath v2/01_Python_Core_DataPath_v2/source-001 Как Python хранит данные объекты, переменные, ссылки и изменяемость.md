# Как Python хранит данные

Новичок часто думает:

```python
x = 10
```

как будто `x` — коробка, в которой лежит число 10.

В Python полезнее другая модель:

> **переменная — это имя, которое ссылается на объект.**

Это объясняет почти всё:
- почему два списка могут неожиданно меняться одновременно;
- почему `id()` совпадает;
- почему `is` и `==` — не одно и то же;
- почему изменяемые объекты опасны в default arguments.

## 1. Имя и объект

```python
x = [1, 2, 3]
y = x
```

Теперь `x` и `y` указывают на **один и тот же список**.

```python
y.append(4)
print(x)
# [1, 2, 3, 4]
```

Мы не «скопировали значение». Мы создали вторую ссылку.

## 2. `==` против `is`

```python
a = [1, 2]
b = [1, 2]
```

```python
a == b   # True
a is b   # False
```

`==` спрашивает:
> равны ли значения?

`is` спрашивает:
> это один и тот же объект?

`is` обычно нужен для singleton-объектов вроде `None`:

```python
if value is None:
    ...
```

а не для сравнения чисел и строк по значению.

## 3. Изменяемые и неизменяемые объекты

### Обычно изменяемые
- `list`
- `dict`
- `set`
- многие пользовательские классы

### Обычно неизменяемые
- `int`
- `float`
- `bool`
- `str`
- `tuple` как контейнер ссылок

Пример строки:

```python
s = "cat"
s += "s"
```

Строка не меняется «на месте» — создаётся новый объект.

## 4. Почему `tuple` не значит «всё внутри immutable»

```python
x = ([1, 2], 10)
x[0].append(3)
```

Это допустимо.

Сам tuple не может заменить ссылку на первый элемент, но первый элемент — изменяемый список.

## 5. Поверхностная и глубокая копия

```python
matrix = [[1, 2], [3, 4]]
copy1 = matrix.copy()
```

Внешний list новый, внутренние lists те же.

```python
copy1[0].append(99)
print(matrix)
```

Изменение видно в исходнике.

Для независимого рекурсивного копирования:

```python
import copy
copy2 = copy.deepcopy(matrix)
```

Но `deepcopy` не нужно использовать автоматически: он может быть дорогим и не всегда соответствует семантике задачи.

## 6. Опасная конструкция `[[0] * m] * n`

```python
grid = [[0] * 3] * 3
grid[0][0] = 1
```

Получится:

```text
[1, 0, 0]
[1, 0, 0]
[1, 0, 0]
```

Потому что все строки — ссылки на один inner list.

Правильно:

```python
grid = [[0] * 3 for _ in range(3)]
```

## 7. Передача аргументов в функцию

Python иногда описывают как «call by object sharing».

```python
def add_item(items):
    items.append(1)
```

Если передать list, функция меняет тот же объект.

Но:

```python
def add_one(x):
    x += 1
```

для `int` создаст новый integer object внутри local name `x`; внешняя ссылка не изменится.

## 8. Mutable default argument

Плохо:

```python
def add_user(name, users=[]):
    users.append(name)
    return users
```

Default object создаётся один раз при определении функции.

Поэтому вызовы делят один list.

Правильно:

```python
def add_user(name, users=None):
    if users is None:
        users = []
    users.append(name)
    return users
```

## 9. Распаковка

```python
a, b = 10, 20
```

Правая часть сначала формирует значения, затем имена получают ссылки.

Поэтому swap:

```python
a, b = b, a
```

работает без temporary variable.

## 10. Что запомнить для интервью

Если спрашивают:
> почему изменение `b` изменило `a`?

Ответ:
> потому что обе переменные ссылались на один mutable object.

Если:
> чем `is` отличается от `==`?

Ответ:
> `is` проверяет identity объекта, `==` — равенство значений.

## Визуализация DataPath

Показывать:
```text
x ─┐
   ├──> [1,2,3]
y ─┘
```

После shallow copy:
```text
x ──> outer A ──> inner
y ──> outer B ──> same inner
```

## Типичные ошибки

- использовать `is` вместо `==`;
- думать, что `list.copy()` делает deep copy;
- умножать nested list через `*`;
- mutable default arguments;
- считать tuple полностью immutable.

## Мини-практика

Предскажите output:

```python
a = [[1], [2]]
b = a.copy()
b[0].append(3)
print(a)
print(b)
```

Затем перепишите так, чтобы `a` не менялся.

## Итог

Главная модель Python:

```text
имя → ссылка → объект
```

Изменяемость и sharing ссылок важнее заучивания отдельных синтаксических правил.
