# Подготовка текста: сохраняем смысл, убираем помехи

Служба поддержки хочет автоматически направлять обращения в нужную очередь. Кажется, что сначала нужно «очистить текст»: убрать знаки, короткие слова, числа и привести всё к одному виду. Но после такой очистки фразы «платёж прошёл» и «платёж не прошёл» могут стать одинаковыми. Данных станет меньше, а задача — сложнее.

Предобработка полезна только относительно задачи. Здесь мы определим единицу наблюдения, отделим технический шум от содержания и построим минимальное воспроизводимое преобразование. В следующем уроке превратим сохранённый текст в числовые признаки.

## Сначала определяем объект и момент решения

Один объект может быть отдельным сообщением, полной перепиской или документом. Для маршрутизации нового обращения доступно только то, что уже написал пользователь. Ответ оператора и итоговая категория, вставленная в шаблон переписки, относятся к будущему. Если они попадут во вход, оценка станет обманчиво высокой.

Прочитайте несколько десятков примеров каждого класса. Проверьте пустые тексты, язык, длину, повторяющиеся шаблоны и согласованность разметки. Дубликаты нельзя просто случайно разделить между обучением и тестом: модель сможет узнавать формулировки вместо обобщения на новые обращения. Несколько сообщений одного диалога часто нужно держать вместе.

Не склеивайте заголовок, сообщение и ответ без обозначения границ. Разные поля имеют разные роли и могут быть доступны в разные моменты.

## Минимальная нормализация с понятным договором

Начнём с безопасного для этой задачи преобразования: приведём Unicode к согласованной форме и заменим последовательности пробельных символов одним пробелом. Сохраним регистр, отрицания, числа и пунктуацию.

```python
import re
import unicodedata

def normalize_text(text: str) -> str:
    if not isinstance(text, str):
        raise TypeError("Ожидается строка")
    text = unicodedata.normalize("NFC", text)
    return re.sub(r"\s+", " ", text).strip()

examples = [
    "  Платёж НЕ прошёл!\nСписали 500 ₽. ",
    "Платёж прошёл.",
    "",
]
print([normalize_text(text) for text in examples])
# ['Платёж НЕ прошёл! Списали 500 ₽.', 'Платёж прошёл.', '']
assert normalize_text(normalize_text(examples[0])) == normalize_text(examples[0])
```

Последняя проверка показывает идемпотентность: повторное применение не меняет уже нормализованный результат. Пустая строка остаётся пустой; дальше нужно явно решить, отклонять её или направлять человеку. Подмена пустого обращения выдуманным текстом только скрывает проблему.

Это не очиститель HTML. Если поле действительно содержит HTML, используйте парсер разметки; регулярное выражение для удаления всего между угловыми скобками может уничтожить полезный текст или обработать документ неверно.

## Какие преобразования требуют проверки

Нижний регистр может помочь классической модели объединить «Ошибка» и «ошибка». Но он же убирает информацию об аббревиатурах. Лемматизация приводит словоформы к словарной форме, например «платежами» к «платёж». Стемминг механически отрезает части слова и может давать несуществующие основы. Ни один метод не является обязательной ступенью перед нейросетью.

Удаление стоп-слов сокращает частые служебные слова. Для тематического поиска часть таких слов бывает малополезна; для тональности отрицание критично. Числа тоже не всегда шум: код ошибки 403 отличается от 500, а сумма списания может влиять на маршрут.

Адреса и телефоны иногда заменяют маркерами, чтобы снизить запоминание персональных данных. Но если задача различает тип контакта, нужно сохранить хотя бы его роль. Преобразование требует собственного теста на реальные форматы, а не надежды на одно универсальное выражение.

## Классическая модель и готовый Transformer

TF-IDF часто выигрывает от умеренной нормализации и символьных n-грамм. У готовой нейронной модели уже есть свой токенизатор и правила, использованные при обучении. Агрессивная внешняя очистка меняет привычное распределение входа и может ухудшить результат.

Поэтому сохраните исходный текст отдельно от обработанного. Это позволяет сравнить варианты на одинаковых данных, разобраться в ошибках и воспроизвести прежний запуск. Версию преобразования храните вместе с моделью.

Преобразования, которые **учатся** по корпусу, например словарь и IDF, обучают только на train. Нормализация пробелов сама по себе не оценивает статистики корпуса, но её выбор по многократным результатам теста всё равно превращает тест в инструмент настройки.

## Самопроверка и практика

1. Почему удаление слова «не» может изменить целевой класс?
2. Почему ответ оператора нельзя использовать для маршрутизации первого сообщения?
3. Чем изменение словаря отличается от простой замены пробелов?
4. Зачем сохранять исходный текст?

Разбор: меняется смысл утверждения; ответ недоступен в момент решения; словарь оценивается по данным и может получить информацию из теста; исходник нужен для анализа ошибок, сравнения преобразований и воспроизводимости.

**Практика.** Составьте шесть обращений: успешный и неуспешный платёж, два кода ошибки, сообщение с переносами и пустую строку. Пропустите их через normalizer. Проверьте, что смысловые пары остались различимыми, повторное применение ничего не меняет, а пустой ввод можно обнаружить. Только затем решайте, что ещё очищать.

В визуальном сценарии подготовки текста оценивайте каждый шаг вопросом: какую помеху он убирает и какую информацию рискует потерять?
