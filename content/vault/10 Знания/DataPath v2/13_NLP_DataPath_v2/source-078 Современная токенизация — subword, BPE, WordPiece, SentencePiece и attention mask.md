# Токенизация: от символов к входу нейронной модели

Человек видит слова, а модель получает последовательность целых чисел. Токенизатор определяет, какие фрагменты текста стоят за этими числами. Ошибка на этом этапе меняет весь дальнейший вход, даже если веса сети загружены правильно.

В отличие от словаря TF-IDF, токены не обязательно являются целыми словами. Это могут быть части слова, отдельные символы или фрагменты байтов. Поэтому число токенов не равно числу слов, особенно для разных языков и форматов вроде кода.

## Зачем нужны части слов

Словарь всех слов огромен: формы, имена и опечатки постоянно добавляют новые варианты. Посимвольная модель избегает неизвестных слов, но делает последовательности длинными. Subword-токенизация ищет компромисс: частые сочетания хранит целиком, редкие раскладывает на меньшие части.

В BPE начинают с небольших единиц и последовательно объединяют часто встречающиеся соседние пары. Учебный пример:

```text
м а м а
м а м е

пара «м а» встречается три раза
после её объединения:
ма ма
ма м е
```

Следующее объединение зависит от всего корпуса и правил разрешения равенств. Это иллюстрация обучения словаря, а не точная токенизация конкретной готовой модели.

WordPiece и алгоритмы семейства Unigram выбирают словарь иначе. SentencePiece — инструмент, который может обучать несколько вариантов токенизации, а не название одного-единственного алгоритма. Для использования модели важнее её конкретный сохранённый токенизатор, чем знакомое общее название.

## Проверяем ID и обратное преобразование

Сделаем прозрачный словарь целых слов, чтобы увидеть договор входа. Он не заменяет subword-токенизатор, но позволяет проверить неизвестные элементы, дополнение и маску без внешних загрузок.

```python
vocabulary = {"[PAD]": 0, "[UNK]": 1, "платёж": 2, "не": 3, "прошёл": 4}
sentences = ["платёж не прошёл", "платёж отменён"]
encoded = [
    [vocabulary.get(word, vocabulary["[UNK]"]) for word in text.split()]
    for text in sentences
]
width = max(map(len, encoded))
padded = [row + [0] * (width - len(row)) for row in encoded]
mask = [[int(token_id != 0) for token_id in row] for row in padded]
print(padded)  # [[2, 3, 4], [2, 1, 0]]
print(mask)    # [[1, 1, 1], [1, 1, 0]]
```

Неизвестное слово получило реальный токен UNK с маской 1. Дополнение получило PAD с маской 0. ID не описывают близость слов: переставить номера можно только вместе с соответствующими строками embedding-таблицы.

## Padding и truncation решают разные проблемы

Padding добавляет технические позиции, чтобы собрать пакет. Truncation отрезает реальный текст до ограничения длины. Маска помогает игнорировать дополнение, но не восстанавливает удалённую информацию.

Если смысл обращения находится в последней строке, обрезание начала до лимита может выбросить ответ. Сначала измерьте длины и долю обрезаемых документов. Затем решите, подходят ли отбор важных полей, разбиение на фрагменты или модель с другой длиной контекста.

Динамическое дополнение до самого длинного объекта текущего пакета обычно экономнее дополнения всех пакетов до глобального лимита. Специальные токены тоже занимают позиции, поэтому полезный бюджет текста может быть меньше указанного максимума.

## Настоящий токенизатор готовой модели

Следующий пример требует библиотеки transformers и заранее сохранённого локального каталога токенизатора. Он намеренно не скачивает файлы автоматически. Путь нужно заменить на ваш каталог; без него этот пример не запускается.

```python
from transformers import AutoTokenizer

tokenizer = AutoTokenizer.from_pretrained(
    "./models/text-encoder", local_files_only=True
)
batch = tokenizer(
    ["Платёж не прошёл.", "Где посылка?"],
    padding=True, truncation=True, max_length=128,
    return_tensors="pt",
)
print(batch["input_ids"].shape)
print(batch["attention_mask"])
print(tokenizer.convert_ids_to_tokens(batch["input_ids"][0]))
```

Токенизатор и веса должны быть одной совместимой версии. Если дообучить собственный словарь, старые веса не начинают автоматически понимать новые строки. Добавление токенов может потребовать изменения embedding-таблицы и обучения новых представлений.

Соглашение маски здесь: 1 — настоящий токен, 0 — дополнение. Оно отличается от некоторых булевых масок PyTorch, где True означает запрет. При переходе между API сверяйте смысл, а не только форму.

## Что проверять на живых примерах

Посмотрите токены русских слов, опечаток, артикулов, emoji и кода. Оцените, сколько токенов приходится на одно слово: чрезмерное дробление увеличивает длину и стоимость обработки. Но меньшее число токенов само по себе не доказывает лучшее понимание.

Для выделения сущностей полезны offsets — соответствие токена фрагменту исходной строки. Одно слово может состоять из нескольких subword-токенов, поэтому метки слов нельзя механически сопоставить позициям токенов. Нужно явно выбрать правило переноса меток и исключения специальных позиций из loss.

## Самопроверка и практика

1. Почему UNK и PAD должны различаться?
2. Почему маска не спасает от потери конца документа?
3. Что сломается при замене словаря без изменения весов?
4. Почему сравнение длины в словах недостаточно?

Разбор: неизвестный элемент существует, дополнение нет; обрезанное содержимое уже отсутствует; ID выберут строки с другим смыслом; модель ограничена токенами, а степень дробления зависит от текста и токенизатора.

**Практика.** В автономном примере ограничьте каждую строку двумя ID до дополнения. Исчезнет «прошёл» из первого сообщения. Отметьте, почему технически корректные форма и маска ещё не означают содержательно пригодный вход. Затем добавьте проверку доли обрезанных сообщений.
