# Оконные функции: сравниваем строки, не теряя детализацию

После `GROUP BY` отдельные заказы исчезают: остаётся агрегат клиента. Но иногда нужно сохранить каждый заказ и рядом показать номер покупки, предыдущую сумму или накопленные расходы. Для этого существуют оконные функции.

Окно определяет набор связанных строк для вычисления. Результат добавляется к каждой исходной строке, а не заменяет группу одной строкой.

## Номер заказа и накопленная сумма

```sql
WITH orders(order_id, client_id, day, amount) AS (
    VALUES (101, 1, '2026-01-01', 100),
           (102, 1, '2026-01-03', 50),
           (103, 2, '2026-01-02', 200),
           (104, 1, '2026-01-03', 80)
)
SELECT
    order_id, client_id, amount,
    ROW_NUMBER() OVER (
        PARTITION BY client_id ORDER BY day, order_id
    ) AS purchase_number,
    SUM(amount) OVER (
        PARTITION BY client_id ORDER BY day, order_id
        ROWS BETWEEN UNBOUNDED PRECEDING AND CURRENT ROW
    ) AS running_total
FROM orders
ORDER BY client_id, day, order_id;
```

У клиента 1 номера покупок будут 1, 2, 3, накопленные суммы — 100, 150, 230. У клиента 2 отдельная группа: номер 1 и сумма 200. Всего сохраняются четыре заказа.

`OVER` превращает вызов в оконное вычисление. `PARTITION BY` разделяет клиентов, `ORDER BY` внутри окна задаёт порядок вычисления. Внешний `ORDER BY` задаёт порядок отображения результата: это отдельная задача.

## Рамка окна отвечает за доступные строки

Для накопленной суммы рамка идёт от начала группы до текущей строки. `ROWS` выражает границы в строках. `UNBOUNDED PRECEDING` означает начало группы, `CURRENT ROW` — текущую строку.

Если не указать рамку, стандартное поведение некоторых агрегатных окон учитывает строки с равными ключами порядка вместе. Поэтому явная рамка и дополнительный уникальный ключ помогают избежать неожиданного скачка суммы при одинаковых датах.

Для признака, который должен использовать только прошлые заказы, закончите рамку на `1 PRECEDING`. Тогда текущая сумма не попадёт в собственный предиктор. У первой строки прошлых событий нет; способ обработки пропуска выбирается по смыслу.

## Предыдущее значение без соединения таблицы с собой

```sql
WITH orders(order_id, amount) AS (
    VALUES (101, 100), (102, 50), (103, 80)
)
SELECT
    order_id, amount,
    LAG(amount) OVER (ORDER BY order_id) AS previous_amount,
    amount - LAG(amount) OVER (ORDER BY order_id) AS change
FROM orders
ORDER BY order_id;
```

Предыдущие суммы: `NULL, 100, 50`. Изменения: `NULL, -50, 30`. `LAG` обращается к предыдущей строке в заданном порядке, `LEAD` — к следующей.

Следующая строка не обязательно означает следующий календарный день. Как и в pandas, нужно различать позицию наблюдения и временное расстояние. В прогнозировании `LEAD` может быть допустим для построения будущей цели, но не для признака, который якобы известен сейчас.

## Ранги и равенство значений

Для сумм 200, 200, 100 функции ведут себя по-разному. `ROW_NUMBER` присваивает три разных номера; без разрешения равенства выбор первых двух может быть неоднозначным. `RANK` даёт 1, 1, 3, оставляя пропуск после равных мест. `DENSE_RANK` даёт 1, 1, 2.

Выбор зависит от вопроса. «Ровно два заказа клиента» и «все заказы на двух лучших уровнях суммы» — разные условия. Не добавляйте уникальный идентификатор в порядок `DENSE_RANK`, если хотите считать одинаковые суммы равными: дополнительный ключ разрушит это равенство.

## Последняя запись и фильтрация

В SQLite результат оконной функции нельзя использовать в `WHERE` того же уровня. Сначала вычислите номер в CTE, затем отфильтруйте:

```sql
WITH
events(client_id, updated_at, version) AS (
    VALUES (1, '2026-01-01', 1), (1, '2026-01-03', 2), (2, '2026-01-02', 1)
),
numbered AS (
    SELECT *,
        ROW_NUMBER() OVER (
            PARTITION BY client_id ORDER BY updated_at DESC, version DESC
        ) AS rn
    FROM events
)
SELECT client_id, updated_at, version
FROM numbered
WHERE rn = 1
ORDER BY client_id;
```

Для клиента 1 останется версия 2, для клиента 2 — версия 1. Такое правило выбора должно иметь смысл в предметной области: идентификатор используется для разрешения равенства, а не как случайная замена времени.

## Самопроверка и практика

1. Чем окно отличается от `GROUP BY`?
2. Зачем два `ORDER BY` в первом запросе?
3. Почему текущий заказ нельзя включать в исторический признак его собственной суммы?
4. Чем `RANK` отличается от `DENSE_RANK`?

Разбор: окно сохраняет детализацию; порядок вычисления и вывода независимы; это передача неизвестной цели в признаки; после равных мест первый ранг оставляет пропуски.

**Практика.** Измените накопленную сумму первого примера на сумму только предыдущих заказов. Для клиента 1 ожидаются `NULL, 100, 150`. Затем оставьте последний заказ каждого клиента: 104 и 103.

В визуализации перемещайте текущую строку и границы окна. Это поможет увидеть разницу между группой клиента и рамкой конкретного вычисления.
