# SQL: от вопроса к выборке строк

Представьте таблицу заказов: одна строка — один заказ. Нужно увидеть три самых дорогих оплаченных заказа. SQL позволяет описать результат: откуда взять строки, какие оставить, какие столбцы показать и как их упорядочить.

Мы используем синтаксис SQLite, потому что он работает во встроенном практикуме DataPath. Учебные таблицы в тексте малы и создаются отдельно; таблица Olist в практикуме имеет собственную схему, которую можно открыть кнопкой «Схема базы».

## Таблица и ключ

Небольшой пример можно выполнить в пустой SQLite-базе:

```sql
CREATE TABLE lesson_orders (
    order_id INTEGER PRIMARY KEY,
    client_id INTEGER NOT NULL,
    amount REAL,
    status TEXT NOT NULL
);
INSERT INTO lesson_orders VALUES
    (101, 1, 100, 'paid'),
    (102, 1, 250, 'paid'),
    (103, 2, 80, 'cancelled'),
    (104, 3, 250, 'paid'),
    (105, 4, NULL, 'pending');
```

Первичный ключ `order_id` различает заказы. Повтор клиента допустим: один человек может сделать несколько заказов. `NOT NULL` запрещает отсутствие обязательного значения, а `NULL` обозначает неизвестное или отсутствующее значение, не ноль и не пустую строку.

Ключ и гранулярность нужно понимать до запроса. Если строка означает товарную позицию заказа, подсчёт строк не даст число заказов без дополнительных действий.

## SELECT и WHERE решают разные задачи

```sql
SELECT order_id, amount
FROM lesson_orders
WHERE status = 'paid' AND amount >= 100;
```

`FROM` задаёт источник, `WHERE` оставляет строки с истинным условием, `SELECT` определяет столбцы результата. В примере остаются заказы 101, 102 и 104. Неоплаченные строки исключены, даже если их сумма подходит под численное условие.

Для сравнения используются `=`, `<>`, `>`, `>=`. Условия объединяются `AND` и `OR`; скобки помогают явно задать порядок. Оператор `IN ('paid', 'pending')` проверяет принадлежность набору значений.

`SELECT *` удобен для первого знакомства со схемой. Для рабочего запроса лучше перечислить нужные столбцы: результат становится понятнее и устойчивее к добавлению полей.

## Порядок результата нужно задавать

```sql
SELECT order_id, amount
FROM lesson_orders
WHERE status = 'paid'
ORDER BY amount DESC, order_id ASC
LIMIT 3;
```

Ожидаемый порядок: 102, 104, 101. `DESC` сортирует сумму по убыванию, `ASC` — идентификатор по возрастанию. Второй ключ разрешает равенство сумм 250.

Без внешнего `ORDER BY` база не обещает полезного порядка строк. `LIMIT 3` без сортировки означает три доступные строки, а не три самых дорогих или последних заказа. Даже если при нескольких запусках порядок совпал, он не становится частью договора.

## Выражения, названия и DISTINCT

```sql
SELECT
    order_id,
    amount,
    amount * 0.9 AS discounted_amount
FROM lesson_orders
WHERE status = 'paid'
ORDER BY order_id;
```

`AS` даёт вычисленному столбцу имя. Результаты скидки: 90, 225 и 225. Вычисление не меняет исходную таблицу: запрос только возвращает результат.

`SELECT DISTINCT client_id` убирает повторные комбинации выбранных столбцов. Если выбрать `client_id, amount`, уникальность относится к паре, а не только к клиенту. Не используйте `DISTINCT` как универсальный способ спрятать дубликаты после неправильного соединения.

## Логика запроса и реальные данные

Полезная модель чтения: источник → фильтр строк → вычисление результата → сортировка → ограничение. База может физически выполнять операции иначе ради скорости, сохраняя смысл запроса.

Для текста используйте одинарные кавычки. Числа не требуют кавычек. Неизвестную сумму ищут через `amount IS NULL`, а не `amount = NULL`: сравнение с неизвестным не даёт обычной истины.

В SQLite типизация гибче, чем во многих серверных базах. Поэтому объявление столбца не отменяет проверки того, какие значения реально попали в источник.

## Самопроверка и практика

1. Почему `LIMIT` не задаёт «лучшие» строки?
2. Почему нужен дополнительный ключ при одинаковых суммах?
3. Чем выбор столбцов отличается от выбора строк?
4. Почему у одного клиента несколько строк не обязательно ошибка?

Разбор: сначала нужен критерий порядка; иначе выбор среди равных неоднозначен; `SELECT` задаёт поля, `WHERE` — условия; строка представляет заказ, а не человека.

**Практика.** Найдите оплаченные заказы с суммой от 200 включительно, выведите идентификатор и сумму, отсортируйте по идентификатору. Ответ: 102 и 104, оба на 250. Затем найдите заказ с неизвестной суммой: 105.

В интерактивной схеме проследите строки через фильтр и сортировку. В практикуме начните с первых запросов к Olist и сверяйте названия полей со схемой. Следующий урок научит сворачивать строки в показатели.
