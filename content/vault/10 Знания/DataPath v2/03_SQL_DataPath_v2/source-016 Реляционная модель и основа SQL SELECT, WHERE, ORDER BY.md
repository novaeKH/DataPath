# Реляционная модель и основа SQL: SELECT, WHERE, ORDER BY

SQL работает не с Python-объектами, а с отношениями — таблицами строк и столбцов. Сильный SQL начинается с трёх вопросов: какая гранулярность таблицы, какие строки нужны и какие столбцы должны попасть в результат.

## Гранулярность таблицы

Перед запросом сформулируйте: одна строка — это заказ, клиент, товар, платеж или событие? Почти все ошибки JOIN/GROUP BY происходят из-за неясной гранулярности.

## SELECT

`SELECT` выбирает выражения результата. Можно вычислять новые колонки: `price * quantity AS revenue`. Alias делает последующие чтение/обсуждение понятнее.

## WHERE

`WHERE` фильтрует строки до агрегации. Условия строятся через `AND`, `OR`, `NOT`; скобки важны из-за precedence. `BETWEEN` обычно включает границы, но для timestamps часто безопаснее писать полуинтервал `>= start AND < next_day`.

## ORDER BY и LIMIT

`ORDER BY` задаёт порядок только финального результата, если нет более специфической конструкции. Без `ORDER BY` порядок строк не гарантируется. `LIMIT` полезен для инспекции, но не заменяет фильтрацию.

## Логический порядок

Упрощённо запрос мыслится как `FROM → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT`. Поэтому alias из SELECT часто нельзя использовать в WHERE того же уровня запроса.

## Практический код

```sql
SELECT
    order_id,
    customer_id,
    price * quantity AS revenue
FROM orders
WHERE status = 'delivered'
  AND order_date >= DATE '2026-01-01'
ORDER BY revenue DESC
LIMIT 100;
```

## Интерактивная визуализация DataPath

Визуализация должна показывать механизм пошагово, позволять менять ключевые параметры и связывать результат с тем, что происходит в коде. Она не должна быть статичной декоративной карточкой.

## Типичные ошибки

- думать, что таблица имеет гарантированный порядок
- использовать `= NULL` вместо `IS NULL`
- не формулировать гранулярность строки
- смешивать AND/OR без скобок
- фильтровать timestamp через ненадёжные строковые сравнения

## Мини-практика

Для таблицы `orders` выберите доставленные за июль 2026 заказы и выведите top-20 по сумме заказа. Затем объясните, какая гранулярность результата.

SQL-запрос — декларативное описание результата. Начинайте с FROM/granularity, затем фильтры, затем форму результата.
