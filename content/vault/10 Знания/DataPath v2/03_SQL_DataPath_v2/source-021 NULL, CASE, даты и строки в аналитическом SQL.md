# NULL, условия и даты: SQL без скрытых допущений

В отчёте средняя сумма заказа неожиданно изменилась после заполнения пропусков. Причина может быть проста: отсутствие значения превратилось в ноль, а ноль участвует в среднем. SQL требует различать неизвестное, пустое и действительно нулевое значение.

Этот урок объединяет операции, которые часто выглядят как мелкий синтаксис, но меняют смысл аналитического результата.

## Три исхода логического условия

Условие в SQL может быть истинным, ложным или неизвестным. Сравнение с `NULL` обычно даёт неизвестность. `WHERE` оставляет только истинные условия.

```sql
WITH payments(id, amount) AS (
    VALUES (1, 100), (2, 0), (3, NULL)
)
SELECT
    id,
    amount,
    amount > 0 AS positive,
    amount IS NULL AS missing
FROM payments
ORDER BY id;
```

Для третьей строки `positive` будет `NULL`, а `missing` — 1. Проверка `amount IS NULL` предназначена именно для поиска отсутствия. `amount = NULL` не является её заменой.

Это объясняет ловушку `NOT IN`, если список содержит `NULL`: отрицание неизвестного не превращается в истину. При поиске отсутствующих соответствий часто яснее использовать `NOT EXISTS`.

## CASE делает правило явным

```sql
WITH payments(id, amount) AS (
    VALUES (1, 100), (2, 0), (3, NULL), (4, -20)
)
SELECT id,
    CASE
        WHEN amount IS NULL THEN 'неизвестно'
        WHEN amount < 0 THEN 'возврат'
        WHEN amount = 0 THEN 'нулевая сумма'
        ELSE 'платёж'
    END AS kind
FROM payments
ORDER BY id;
```

Условия проверяются сверху вниз; возвращается результат первой подходящей ветви. Поэтому порядок важен. Если более широкое условие стоит раньше узкого, узкая ветвь может никогда не использоваться.

Если не написать `ELSE` и ни одна ветвь не подходит, результат будет `NULL`. Иногда это нужно, но случайно пропущенная ветвь создаёт труднообъяснимые пропуски.

## Заполнение и безопасное деление

`COALESCE(a, b, c)` возвращает первое непустое значение. Используйте его, когда запасное значение осмысленно. Отсутствие заказов в полном журнале может означать ноль заказов; неизвестная сумма существующего заказа не обязана быть нулём.

```sql
WITH groups(name, conversions, visits) AS (
    VALUES ('a', 2, 10), ('b', 0, 0)
)
SELECT
    name,
    1.0 * conversions / NULLIF(visits, 0) AS conversion_rate
FROM groups
ORDER BY name;
```

Для группы `a` доля равна 0.2. Для `b` — `NULL`: наблюдений нет, поэтому доля не определена. `NULLIF(visits, 0)` превращает нулевой знаменатель в пропуск. Множитель `1.0` переводит арифметику в дробную.

Заменять неопределённую долю нулём ради красивого графика опасно: «никто не пришёл» и «пришли, но никто не купил» — разные ситуации.

## Даты и интервалы в SQLite

В учебных примерах используем ISO-формат `YYYY-MM-DD`. SQLite предоставляет функции `date`, `datetime`, `strftime` и `julianday`.

```sql
SELECT
    date('2026-01-31', '+1 day') AS next_day,
    strftime('%Y-%m', '2026-01-31') AS month,
    julianday('2026-02-03') - julianday('2026-01-31') AS days;
```

Результат: 1 февраля, месяц `2026-01`, разность 3 дня. Для календарных групп используйте год и месяц вместе: номер месяца без года объединит январь разных лет.

Для временной метки удобны полуоткрытые границы:

```sql
WITH events(event_id, happened_at) AS (
    VALUES (1, '2026-01-31 23:59:59'), (2, '2026-02-01 00:00:00')
)
SELECT event_id
FROM events
WHERE happened_at >= '2026-01-01'
  AND happened_at < '2026-02-01';
```

Останется событие 1. Такой интервал не требует угадывать последнюю долю секунды месяца. Строковое сравнение корректно здесь потому, что формат и часовой пояс согласованы.

## Строки и нормализация

`trim` убирает внешние пробелы, `lower` меняет регистр в поддерживаемом движком объёме, `substr` выбирает фрагмент, `||` соединяет строки. Не предполагайте, что базовые функции SQLite автоматически дают полноценную Unicode-нормализацию для любого языка.

Очистка идентификатора может объединить разные реальные сущности. Прежде чем убрать знаки или ведущие нули, уточните формат: почтовый индекс и номер договора обычно не являются числами для арифметики.

## Самопроверка и практика

1. Почему сравнение с `NULL` не заменяет `IS NULL`?
2. Что означает пропуск доли при нулевом знаменателе?
3. Почему год нужен рядом с месяцем?
4. Почему верхняя граница периода часто исключается?

Разбор: неизвестность требует отдельной проверки; показатель не определён; иначе объединятся разные годы; полуоткрытые интервалы соседствуют без пересечения и проблем точности.

**Практика.** Для сумм `100, 0, NULL` сравните `AVG(amount)` и `AVG(COALESCE(amount, 0))`. Ответы: 50 и примерно 33.33. Объясните, какое новое предположение внесло заполнение.

В визуализации проследите, какие строки остаются после условий с пропусками. Следующий урок объединит эти операции в аналитические задачи.
