# Подзапросы и CTE: сложный вопрос по понятным шагам

Нужно найти клиентов, чьи общие траты выше среднего по клиентам. Здесь два уровня: сначала сумма заказов каждого клиента, затем среднее этих сумм. Попытка смешать оба уровня в одной строке часто приводит к ошибке или другому показателю.

Подзапрос позволяет использовать результат одного запроса внутри другого. CTE даёт промежуточному результату имя, чтобы рассуждение читалось последовательно.

## Сначала определим показатель вручную

У клиента 1 заказы 100 и 50, у клиента 2 — 200, у клиента 3 — 10. Суммы по клиентам: 150, 200, 10. Средняя сумма клиента равна 120. Значит, подходят клиенты 1 и 2.

Средняя сумма отдельного заказа была бы `360/4 = 90`. Это другой показатель. Прежде чем писать SQL, нужно решить, по каким объектам вычисляется среднее.

## Именуем каждый уровень

```sql
WITH
orders(client_id, amount) AS (
    VALUES (1, 100.0), (1, 50.0), (2, 200.0), (3, 10.0)
),
client_totals AS (
    SELECT client_id, SUM(amount) AS total
    FROM orders
    GROUP BY client_id
),
reference AS (
    SELECT AVG(total) AS mean_total
    FROM client_totals
)
SELECT client_id, total
FROM client_totals
WHERE total > (SELECT mean_total FROM reference)
ORDER BY client_id;
```

`WITH` задаёт несколько CTE через запятую. `client_totals` имеет одну строку на клиента, `reference` — одну строку на весь набор. Последний запрос сравнивает готовые суммы с одним числом.

Результат: клиент 1 с суммой 150 и клиент 2 с суммой 200. Чтобы отладить запрос, временно замените последний `SELECT` на просмотр нужного промежуточного CTE. Так проверяется каждый смысловой шаг.

## Подзапрос как число, таблица и условие существования

Скалярный подзапрос должен выражать одно значение, например среднее. Подзапрос в `FROM` представляет таблицу. Подзапрос с `EXISTS` отвечает только на вопрос, есть ли совпадающая строка.

```sql
WITH
clients(client_id) AS (VALUES (1), (2), (3)),
orders(client_id, amount) AS (VALUES (1, 100), (1, 50), (2, 200))
SELECT c.client_id
FROM clients c
WHERE EXISTS (
    SELECT 1
    FROM orders o
    WHERE o.client_id = c.client_id AND o.amount >= 100
)
ORDER BY c.client_id;
```

Получатся клиенты 1 и 2, каждый по одному разу. `EXISTS` не размножает клиента по числу подходящих заказов: он проверяет логическое условие. Выбранная константа `1` не означает подсчёт.

Подзапрос обращается к `c.client_id` внешнего запроса, поэтому называется коррелированным. Это описание зависимости, а не обещание конкретного физического плана: оптимизатор может преобразовать выполнение.

## Почему NOT EXISTS часто понятнее NOT IN

`NOT EXISTS` выражает отсутствие подходящей строки. `NOT IN` при наличии `NULL` в подзапросе может неожиданно вернуть неизвестность вместо истины и исключить ожидаемые строки.

Если нужно найти клиентов без заказов, удобно явно написать отсутствие совпадения по ключу. При этом следует определить смысл неизвестных ключей в исходных данных, а не считать их обычной категорией.

```sql
WITH
clients(client_id) AS (VALUES (1), (2), (3)),
orders(client_id) AS (VALUES (1), (1), (2), (NULL))
SELECT c.client_id
FROM clients c
WHERE NOT EXISTS (
    SELECT 1 FROM orders o WHERE o.client_id = c.client_id
)
ORDER BY c.client_id;
```

Результат — клиент 3. Неизвестный ключ заказа не становится совпадением для каждого клиента.

## CTE помогает читать, но не гарантирует ускорение

CTE существует в рамках одного SQL-выражения. Он не обязательно сохраняется как физическая временная таблица. База может встроить вычисление или материализовать его; детали зависят от движка и запроса.

Поэтому сначала добейтесь правильного результата и ясной структуры, затем измеряйте производительность через план и время выполнения. Разделение на CTE не является универсальной оптимизацией, но делает уровни данных проверяемыми.

Не превращайте каждый простой `WHERE` в отдельный CTE. Хорошее имя обозначает смысл: `paid_orders`, `client_totals`, `latest_status`. Набор имён `t1`, `t2`, `t3` скрывает рассуждение.

## Самопроверка и практика

1. Почему среднее сумм клиентов отличается от среднего заказа?
2. Как проверить промежуточную агрегацию?
3. Почему `EXISTS` не размножает строки?
4. Почему наличие CTE не доказывает ускорение?

Разбор: различаются объекты и веса; вывести промежуточный результат; возвращается истинность существования, а не пары; физический план выбирает база.

**Практика.** В первом примере добавьте клиенту 3 заказ на 350. Его сумма станет 360, среднее трёх клиентов — примерно 236.67. Должен остаться только клиент 3. Проверьте сначала суммы, затем среднее, затем финальный отбор.

В визуализации пройдите именованные промежуточные таблицы. Следующий урок позволит сравнивать строку с соседями без сворачивания всей группы.
