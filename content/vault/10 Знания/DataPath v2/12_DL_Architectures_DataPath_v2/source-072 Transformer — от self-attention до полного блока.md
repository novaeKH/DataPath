# Transformer: собираем знакомые операции в один блок

Attention умеет смешивать информацию разных позиций. Но для полезной модели нужны ещё преобразование признаков каждой позиции, устойчивое обучение и способ сохранить исходный сигнал. Transformer объединяет эти операции в повторяемый блок.

После этого урока вы должны суметь проследить форму тензора через блок, объяснить разницу между кодировщиком и авторегрессионной моделью и найти утечку будущего в маске. Для этого достаточно тензоров, embeddings, attention и остаточных связей из предыдущих глав.

## Что попадает в блок

Токенизатор превращает текст в ID, таблица embeddings — в векторы. Добавляется информация о позиции, потому что одни и те же слова в разном порядке могут выражать разный смысл. Получаем тензор `[B,L,d]`: пакет, длина последовательности, размер представления.

Позиционную информацию можно добавлять обучаемыми векторами или задавать другими схемами. В нашем примере будет простая обучаемая таблица позиций. Она имеет максимальную длину; более длинная последовательность потребует другого решения. Нельзя считать, что любая позиционная схема автоматически обобщается на произвольную длину.

## Два преобразования и два коротких пути

Рассмотрим вариант Pre-Norm:

$$
U=X+\operatorname{Attention}(\operatorname{LN}(X)),
$$

$$
Y=U+\operatorname{FFN}(\operatorname{LN}(U)).
$$

LayerNorm, обозначенная LN, нормирует признаки отдельной позиции. Attention обменивается информацией между позициями. FFN — небольшая полносвязная сеть с нелинейностью, которая применяется к каждой позиции отдельно с общими весами. Она меняет представление токена, но сама по себе не читает соседей.

Обычно FFN сначала расширяет размер признаков, например с 16 до 64, а затем возвращает к 16. Возврат необходим для сложения с остаточной ветвью. Если бы обе операции FFN были линейными без нелинейности между ними, их можно было бы свернуть в одну.

В Post-Norm нормировка стоит после сложения. Это другой порядок вычислений, а не другая задача. Не смешивайте формулы двух вариантов при ручной проверке.

## Рабочий блок с маской дополнения

Код создаёт две последовательности. Нулевой ID — дополнение. Мы сначала проверяем формы и обработку маски, не оценивая качество необученной модели.

```python
import torch
from torch import nn

torch.manual_seed(7)
ids = torch.tensor([[1, 2, 3, 0], [4, 5, 0, 0]])
token_embedding = nn.Embedding(10, 16, padding_idx=0)
position_embedding = nn.Embedding(8, 16)
positions = torch.arange(ids.shape[1])
X = token_embedding(ids) + position_embedding(positions)

block = nn.TransformerEncoderLayer(
    d_model=16, nhead=4, dim_feedforward=64,
    dropout=0.0, batch_first=True, norm_first=True,
)
padding = ids.eq(0)
Y = block(X, src_key_padding_mask=padding)
print(Y.shape)  # torch.Size([2, 4, 16])

valid = (~padding).unsqueeze(-1)
pooled = (Y * valid).sum(1) / valid.sum(1).clamp_min(1)
head = nn.Linear(16, 3)
print(head(pooled).shape)  # torch.Size([2, 3])
```

Маска не даёт читать дополнение как ключ. Но представления в самих технических позициях не обязаны стать нулевыми, поэтому при усреднении мы снова исключаем их. Это частая ошибка: наличие одной маски в attention не делает любое последующее вычисление корректным.

Четыре головы делят размер 16 на четыре части по четыре координаты. Сам блок возвращает исходный размер представления, что позволяет повторять его несколько раз.

## Кодировщик, авторегрессия и перевод

**Encoder-only** обрабатывает доступную последовательность с двусторонним контекстом. Подходит для классификации готового текста и извлечения признаков. **Decoder-only** ограничивает self-attention прошлым и текущей позицией; выход используется для предсказания следующего токена. **Encoder–decoder** сначала кодирует вход, а затем генерирует выход, обращаясь к входу через cross-attention.

Причинная маска для четырёх позиций имеет вид:

```text
можно нельзя нельзя нельзя
можно можно  нельзя нельзя
можно можно  можно  нельзя
можно можно  можно  можно
```

При обучении следующий токен сдвигается относительно входа: из «я люблю» предсказываем «люблю Python». Нельзя подать истинное продолжение в доступный контекст той позиции, которая должна его угадать. Все обучающие позиции можно обработать параллельно с правильной маской; при генерации следующий неизвестный токен всё равно появляется последовательно.

## Почему длинный контекст стоит дорого

Обычный attention сравнивает каждую позицию с каждой. Число пар растёт как $L^2$, а FFN обрабатывает позиции отдельно и растёт по длине линейно при фиксированной ширине. Увеличение длины с 512 до 1024 даёт вчетверо больше пар, но не означает автоматически вчетверо больше времени всей модели.

При генерации можно сохранять уже вычисленные ключи и значения прошлых токенов — KV cache. Это сокращает повторные вычисления, но занимает память, которая растёт с длиной и размером пакета. Это не долговременная память пользователя и не база знаний; это промежуточные тензоры конкретного вычисления.

## Типичные ошибки и чтение схемы

Transformer — не синоним языковой модели. Одни и те же блоки применяют к тексту, изображениям и другим последовательностям; задачу определяют вход, маски, выходная голова и обучение.

В интерактивном блоке пройдите путь одного тензора. На каждом сложении проверьте одинаковость форм, на attention — доступность ключей, на FFN — отсутствие обмена между позициями. Это полезнее, чем заучивать названия всех популярных архитектур.

Не путайте LayerNorm с BatchNorm: в рассматриваемом блоке нормировка не требует оценивать статистику разных объектов пакета. Однако это не отменяет переключение `train()`/`eval()` для dropout и других модулей.

## Самопроверка и практика

1. Какая часть блока смешивает позиции, а какая — признаки одной позиции?
2. Почему FFN возвращает размер $d$?
3. Зачем исключать дополнение из усреднения после attention?
4. Почему обучение по всем позициям параллельно не делает генерацию всей строки одновременной?

Разбор: attention смешивает позиции, FFN преобразует каждую отдельно; нужен остаточный путь одинаковой формы; выход технических позиций может быть ненулевым; при обучении известны целевые токены и действует маска, при генерации будущие токены ещё неизвестны.

**Практика.** Добавьте к обеим строкам примера два нулевых ID. В режиме `eval()` и без dropout сравните усреднённые представления настоящих токенов с исходными: они должны совпасть с численной точностью. Если усреднить все позиции без маски, равенство нарушится. Объясните причину до запуска.

Далее соберём не только архитектуру, но и полный цикл обучения с Dataset, проверкой качества и сохранением весов.
