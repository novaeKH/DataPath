# Рекуррентная сеть: как учитывать порядок событий

Покупатель открыл каталог, добавил товар и оплатил заказ. Тот же набор событий в другом порядке имеет другой смысл. Если усреднить их признаки, порядок исчезнет. Рекуррентная нейронная сеть, или RNN, обрабатывает последовательность по шагам и переносит между ними небольшое внутреннее состояние.

Ранее мы применяли один фильтр ко многим положениям изображения. Здесь один вычислительный блок применяется ко многим моментам времени. Повторно используются **веса**, а состояние меняется после каждого элемента.

## Состояние — сжатое описание прошлого

Пусть $x_t$ — признаки события на шаге $t$, а $h_{t-1}$ — состояние после предыдущего события. Простейшая RNN вычисляет:

$$
h_t=\tanh(W_xx_t+W_hh_{t-1}+b).
$$

Матрица $W_x$ преобразует новое событие, $W_h$ — предыдущее состояние, $b$ задаёт смещение. Tanh ограничивает каждую координату интервалом от −1 до 1 и делает преобразование нелинейным. Состояние не хранит всю историю без потерь: сеть учится оставлять то, что помогает конечной задаче.

Начальное состояние часто нулевое. Для независимого нового пользователя его нужно начать заново, иначе информация о предыдущем пользователе попадёт в чужой прогноз.

## Три шага вручную

Упростим всё до одного числа: $W_x=1$, $W_h=0.5$, $b=0$, входы равны 1, 0, 0.

```python
import math

state = 0.0
for event in [1.0, 0.0, 0.0]:
    state = math.tanh(event + 0.5 * state)
    print(round(state, 3))
# 0.762
# 0.363
# 0.180
```

Первое событие меняет состояние с нуля примерно до 0.762. На втором шаге новый вход нулевой, но сеть не возвращается сразу в ноль: остаётся след прошлого. На третьем он уменьшается снова. Это простой пример затухания памяти, а не универсальная скорость забывания всех RNN.

Переставьте единицу в конец: последнее состояние станет около 0.762 вместо 0.180. Состав событий тот же, но порядок влияет на результат.

## Что предсказываем: один ответ или ответ на каждом шаге

Для классификации всей последовательности можно передать последнее содержательное состояние в линейный классификатор. Например, решить, похожа ли сессия на бота. Для прогноза следующего события выход нужен после каждого шага. Тогда один и тот же выходной слой применяется ко всем состояниям.

Пример ниже показывает формы для двух последовательностей по четыре события; у каждого события три признака.

```python
import torch
from torch import nn

torch.manual_seed(7)
events = torch.randn(2, 4, 3)
rnn = nn.RNN(input_size=3, hidden_size=5, batch_first=True)
states, final_state = rnn(events)
print(states.shape)       # torch.Size([2, 4, 5])
print(final_state.shape)  # torch.Size([1, 2, 5])
print(torch.allclose(states[:, -1], final_state[0]))  # True
```

`states` содержит состояние верхнего слоя для каждой позиции. `final_state` содержит последние состояния всех слоёв и направлений. В нашем однослойном однонаправленном примере первые элементы этих представлений легко сопоставить. Для многослойной или двунаправленной сети формы и смысл уже отличаются.

## Как градиент проходит через время

При обучении рекурсию мысленно разворачивают в цепочку копий одного блока. Ошибка последнего ответа влияет на ранний шаг через все промежуточные переходы. Это обратное распространение через время, или BPTT.

Если производные вдоль пути часто меньше единицы по модулю, их произведение может стать очень малым. Тогда далёкое событие почти не получает обучающего сигнала. Если множители слишком велики, градиент может резко вырасти. Ограничение нормы градиента помогает против взрыва, но не восстанавливает исчезнувший сигнал.

Вычислить следующий шаг обычной RNN нельзя до получения предыдущего состояния. Это ограничивает параллельную обработку по времени, хотя разные последовательности пакета обрабатываются вместе.

## Длина последовательностей и утечки

Для пакета последовательности часто дополняют техническими нулями до общей длины. Но нулевой вход не означает «ничего не делать»: состояние всё равно проходит через веса и tanh. Последнее состояние после дополнения может отличаться от последнего реального состояния. Используйте реальные длины, упаковку последовательностей или явную маску; следующий урок покажет упаковку.

Двунаправленная RNN читает данные в обе стороны. Это допустимо, когда весь текст уже известен, например при классификации готового отзыва. Для онлайн-прогноза нельзя передавать события, которые произошли после момента решения. При этом читать в обе стороны полностью известное историческое окно допустимо: утечку определяет доступность данных, а не название архитектуры.

## Самопроверка и практика

1. Что общее у шагов RNN: веса или состояния?
2. Почему нули дополнения могут изменить итоговое представление?
3. Почему ограничение градиента не решает проблему забывания?
4. Когда двунаправленная сеть использует недопустимое будущее?

Разбор: веса общие, состояния зависят от истории; даже нулевой вход запускает переход состояния; clipping ограничивает большие значения, но не увеличивает исчезнувшие; утечка возникает, если вход содержит недоступные в момент прогноза события.

**Практика.** Измените в числовом примере коэффициент памяти с 0.5 на 0 и на 0.9. Предскажите, в каком случае единица исчезнет сразу после следующего нулевого входа. При нуле состояния будут примерно `[0.762, 0, 0]`. Сравните это с интерактивным блоком состояния.
