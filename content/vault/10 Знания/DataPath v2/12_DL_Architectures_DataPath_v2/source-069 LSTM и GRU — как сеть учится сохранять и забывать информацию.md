# LSTM и GRU: управляемая память последовательности

В простой RNN старое состояние на каждом шаге целиком проходит через матрицу и нелинейность. Из-за этого важное раннее событие может быстро потерять влияние. Представим длинную сессию: пользователь уже выбрал город доставки, затем просмотрел десятки товаров. Город полезно сохранить, а случайные просмотры — не обязательно.

LSTM и GRU добавляют обучаемые **ворота**: коэффициенты от нуля до единицы, управляющие потоком информации. Это не ручные правила «помнить город», а функции текущего входа и прошлого состояния. Смысл сохраняемых признаков формируется при обучении.

## LSTM разделяет память и видимый выход

У LSTM есть два состояния. $c_t$ — состояние памяти, а $h_t$ — выход, доступный следующим вычислениям. Три группы коэффициентов управляют забыванием, записью и выдачей результата:

$$
c_t=f_t\odot c_{t-1}+i_t\odot \widetilde c_t,
\qquad
h_t=o_t\odot\tanh(c_t).
$$

Символ $\odot$ означает покоординатное умножение. Forget gate $f_t$ задаёт долю старой памяти, input gate $i_t$ — долю новой записи, output gate $o_t$ — долю видимого выхода. Кандидат $\widetilde c_t$ — предложенное новое содержимое. Ворота обычно получают через sigmoid, кандидат — через tanh.

Для векторного состояния разные координаты могут одновременно сохранять старое, забывать и принимать новое. Поэтому неверно представлять один общий выключатель памяти для всей сети.

## Один шаг с конкретными числами

Пусть старая память равна 2, кандидат −1, ворота забывания 0.9, записи 0.2 и выхода 0.5. Тогда:

$$
c_t=0.9\cdot2+0.2\cdot(-1)=1.6,
\qquad h_t=0.5\tanh(1.6)\approx0.461.
$$

Память и выход не равны. Большая по модулю память не обязана полностью проявляться в выходе: его регулируют tanh и выходные ворота.

```python
import math

previous = 2.0
forget, write, output = 0.9, 0.2, 0.5
candidate = -1.0
memory = forget * previous + write * candidate
hidden = output * math.tanh(memory)
print(round(memory, 3), round(hidden, 3))  # 1.6 0.461
```

Если поставить забывание 1 и запись 0, память сохранится в точности. Прямой аддитивный путь помогает переносить информацию и градиент на большие расстояния. Но LSTM не гарантирует бесконечную память: ворота тоже обучаются, а их значения могут ослаблять сигнал.

## GRU объединяет механизмы

У GRU нет отдельного состояния памяти $c_t$. Одно состояние смешивает старую информацию с кандидатом. В соглашении PyTorch:

$$
h_t=z_t\odot h_{t-1}+(1-z_t)\odot\widetilde h_t.
$$

Update gate $z_t$, близкий к единице, сохраняет прежнее состояние. Reset gate влияет на использование старого состояния при построении кандидата. В некоторых учебниках коэффициенты в формуле смешивания поменяны местами, поэтому значение «большие ворота» всегда сверяйте с формулой.

GRU обычно имеет меньше параметров при одинаковом размере состояния. Это не доказывает, что она всегда быстрее или хуже LSTM: качество и время сравнивают на конкретных данных и устройстве.

## Последовательности разной длины без ложных событий

Ниже первая последовательность содержит четыре события, вторая — два. Остальные позиции второго объекта являются дополнением, а не наблюдениями. Упаковка сообщает LSTM реальные длины.

```python
import torch
from torch import nn
from torch.nn.utils.rnn import pack_padded_sequence

torch.manual_seed(7)
events = torch.randn(2, 4, 3)
lengths = torch.tensor([4, 2])
events[1, 2:] = 0
packed = pack_padded_sequence(
    events, lengths.cpu(), batch_first=True, enforce_sorted=False
)
lstm = nn.LSTM(input_size=3, hidden_size=5, batch_first=True)
packed_output, (hidden, memory) = lstm(packed)
print(hidden.shape, memory.shape)  # оба [1, 2, 5]
classifier = nn.Linear(5, 2)
logits = classifier(hidden[-1])
print(logits.shape)  # torch.Size([2, 2])
```

Последнее состояние относится к последнему настоящему событию каждого объекта. Классификатор получает по пяти признакам на последовательность и выдаёт два логита. Для CrossEntropyLoss нужны целочисленные метки классов, а не предварительно вычисленный softmax.

## Ошибки, которые не исправляются новой архитектурой

Не переносите состояния между независимыми объектами. При обработке одной длинной истории по фрагментам перенос может быть намеренным; тогда состояние отсоединяют от старого вычислительного графа, если не хотят хранить и дифференцировать всю историю. Это усечённое BPTT, а не просто «ускорение без изменений»: дальний обучающий сигнал обрезается.

`eval()` не замораживает веса, а `requires_grad=False` не переключает режим dropout. У рекуррентных модулей встроенный dropout применяется между слоями, поэтому на однослойной сети не стоит ожидать от этого параметра регуляризации выхода каждого шага.

И главное: LSTM не исправит утечку будущего, случайное смешивание пользователей в разбиении или неправильные метки. Сначала сравните с понятным baseline на лаговых признаках, затем усложняйте архитектуру.

## Самопроверка и практика

1. Зачем отличать память $c_t$ от выхода $h_t$?
2. Какие ворота сохранят старую память без записи новой?
3. Почему padding нельзя просто считать реальным нулевым событием?
4. Почему меньшее число параметров GRU не гарантирует лучшего результата?

Разбор: сеть может хранить информацию, не выдавая её целиком; нужны $f=1$ и $i=0$; даже нулевой вход меняет состояние; результат зависит от структуры задачи, данных и режима обучения.

**Практика.** В ручном примере замените forget gate на 0.1 при остальных прежних значениях. Получатся память 0 и выход 0. Затем оставьте память 1.6, но задайте выходные ворота 0: память остаётся, наружу выходит ноль. Сопоставьте эти два случая в интерактивном блоке.

Далее научимся представлять дискретные категории и слова векторами — входами последовательностных моделей.
