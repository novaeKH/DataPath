# scikit-learn: один интерфейс для разных моделей

Мы уже умеем хранить данные, писать функции и вычислять взвешенную сумму признаков. Следующий шаг — поручить библиотеке поиск параметров модели. scikit-learn использует похожие методы для множества алгоритмов, поэтому однажды понятый интерфейс переносится на новые модели.

В этом уроке важен жизненный цикл объекта: настройка → обучение → применение. Математику отдельных алгоритмов подробно разберём в ML-блоке.

## Данные и задача

Пусть нужно отличать три вида ирисов по четырём измерениям цветка. Это классификация: целевая переменная принимает одну из нескольких меток. Признаки обозначим `X`, правильные ответы — `y`.

```python
from sklearn.datasets import load_iris
from sklearn.model_selection import train_test_split
from sklearn.linear_model import LogisticRegression
from sklearn.metrics import accuracy_score

X, y = load_iris(return_X_y=True)
X_train, X_test, y_train, y_test = train_test_split(
    X, y, test_size=0.2, stratify=y, random_state=42
)
model = LogisticRegression(max_iter=1000)
model.fit(X_train, y_train)
predictions = model.predict(X_test)

print(X_train.shape, X_test.shape)   # (120, 4) (30, 4)
print(predictions.shape)            # (30,)
print(accuracy_score(y_test, predictions))
```

Набор встроен в библиотеку и не требует внешнего файла. Разбиение оставляет 30 объектов для проверки. `stratify=y` старается сохранить доли классов, `random_state` делает выбранное разбиение воспроизводимым. Конкретное качество — характеристика этого учебного примера, а не обещание будущей модели.

## Создание объекта ещё не является обучением

`LogisticRegression(max_iter=1000)` создаёт объект с настройками. Весов, найденных по этим данным, ещё нет. `fit(X_train, y_train)` ищет параметры, связывающие признаки с ответами.

Настройки, заданные до обучения, называются гиперпараметрами. Найденные веса — параметры обученной модели. Во многих объектах scikit-learn обученные атрибуты имеют завершающее подчёркивание, например `classes_` и `coef_`.

Название estimator объединяет объекты, поддерживающие обучение через `fit`. Среди них есть предсказатели и преобразователи. Наличие общего интерфейса не означает, что всем алгоритмам подходят одинаковые данные и настройки.

## predict и predict_proba дают разные результаты

```python
probabilities = model.predict_proba(X_test)
print(probabilities.shape)   # (30, 3)
print(model.classes_)        # [0 1 2]
print(probabilities[0].sum()) # около 1.0
```

`predict` возвращает выбранную метку класса. `predict_proba` возвращает по одной оценке вероятности на класс. Порядок столбцов нужно читать через `classes_`, а не угадывать.

Оценка 0.8 не является обещанием правильности каждого конкретного ответа. Позже разберём калибровку: соответствует ли среди прогнозов около 0.8 реальная доля успеха примерно 80%.

Не каждый классификатор поддерживает вероятности. `decision_function` может возвращать числовую оценку уверенности, которая не ограничена интервалом от нуля до единицы и не должна автоматически называться вероятностью.

## Преобразователи тоже обучаются

```python
from sklearn.preprocessing import StandardScaler

scaler = StandardScaler()
scaler.fit(X_train)
scaled_train = scaler.transform(X_train)
scaled_test = scaler.transform(X_test)

print(scaled_train.shape)   # (120, 4)
print(scaler.mean_.shape)   # (4,)
```

`fit` вычислил среднее и масштаб каждого признака по обучающим строкам. `transform` применяет сохранённые значения. Для тестовых данных нельзя заново вызывать `fit`: иначе изменятся параметры преобразования и смысл проверки.

`fit_transform` объединяет обучение и преобразование одного набора. Его обычно используют на обучающей части, а `transform` — на проверочной. Это различие относится не только к масштабированию, но и к заполнению пропусков, словарю текста и уменьшению размерности.

## Форма, порядок и оценка результата

`X` обычно имеет форму `(n_samples, n_features)`. Для одного объекта всё равно нужна двумерная таблица: `X_test[:1]`, а не случайный одномерный вектор. При применении порядок признаков должен совпадать с обучением.

Метод `score` использует стандартную метрику конкретного типа модели. У классификатора это часто accuracy, у регрессора — R². Поэтому для отчёта полезно вычислять выбранную метрику явно: её смысл не должен зависеть от того, какой объект подставили.

Повторный `fit` обычно переобучает объект. Для последовательного дообучения существуют отдельные возможности вроде `partial_fit`, поддерживаемые не всеми алгоритмами.

## Самопроверка и практика

1. Чем настройка объекта отличается от обучения?
2. Почему scaler нельзя обучать отдельно на тесте?
3. Где узнать порядок столбцов вероятностей?
4. Почему одна строка данных всё ещё имеет две оси?

Разбор: настройки заданы человеком, параметры найдены по данным; параметры преобразования должны быть общими и не использовать проверку; в `classes_`; оси обозначают объекты и признаки, даже если объект один.

**Практика.** Получите прогнозы для первых двух тестовых объектов и сопоставьте каждый столбец вероятности с классом. Затем сравните `scaler.mean_` со средним только `X_train`. Они должны совпасть.

В визуализации наблюдайте появление обученных параметров после `fit`. Следующий урок объединит преобразования и модель, чтобы правильный порядок выполнялся автоматически.
