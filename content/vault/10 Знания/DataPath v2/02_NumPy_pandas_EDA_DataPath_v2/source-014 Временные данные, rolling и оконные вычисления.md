# Временные данные: что было известно в момент прогноза

Для прогноза покупки завтра полезно знать последние покупки клиента. Но если вычислить «среднюю сумму за неделю» с включением завтрашней покупки, модель получит ответ заранее. Такая ошибка может скрываться в одной операции `rolling`.

Временной признак — не просто число из таблицы с датами. У него есть момент доступности, порядок событий и границы окна. Разберём эти условия на небольшой истории продаж.

## Дата должна стать временным типом

```python
import pandas as pd

sales = pd.DataFrame({
    "day": ["2026-01-01", "2026-01-02", "2026-01-03", "2026-01-04"],
    "amount": [10., 20., 30., 40.],
})
sales["day"] = pd.to_datetime(sales["day"], errors="raise")
sales = sales.sort_values("day").set_index("day")
```

Строка с датой и временная метка поддерживают разные операции. `errors="raise"` помогает сразу обнаружить неверный формат. Для неоднозначных дат лучше явно указать ожидаемый формат.

Если события приходят из разных часовых поясов, приведите их к общей временной шкале, часто UTC. Простое присвоение часового пояса локальному времени отличается от перевода уже известного момента в другой пояс. Переходы летнего времени также могут создавать повторяющиеся или отсутствующие часы.

## Сдвиг создаёт доступное прошлое

```python
sales["previous_amount"] = sales["amount"].shift(1)
print(sales["previous_amount"].tolist())   # [nan, 10.0, 20.0, 30.0]
```

`shift(1)` перемещает значения на одну позицию. Для 3 января теперь доступна сумма 2 января. У первого дня прошлого наблюдения нет, поэтому появился пропуск.

Сдвиг на одну строку не обязательно означает вчера. Если 2 января отсутствует, предыдущая строка для 3 января может относиться к 1 января. Сначала выясните, представляет таблица все календарные дни или только дни с событиями.

## Скользящее окно: строки и календарное время

```python
sales["past_two_mean"] = sales["amount"].shift(1).rolling(2).mean()
print(sales["past_two_mean"].tolist())   # [nan, nan, 15.0, 25.0]
```

Для 3 января сначала берутся доступные прошлые значения 10 и 20, затем считается среднее 15. Для 4 января — 20 и 30, среднее 25. Без `shift` окно включило бы текущую сумму, которую мы как раз хотим предсказывать.

`rolling(2)` означает два наблюдения. `rolling("2D")` означает временной интервал в два дня и требует временного индекса. Число событий в таком интервале может меняться. Параметр `closed` задаёт включение границ, а `min_periods` — минимальное число наблюдений для результата.

Граница — часть определения признака. «За предыдущие 30 дней» обычно означает интервал до момента прогноза, но включение самого момента нужно оговорить отдельно.

## Отдельная история каждого объекта

Если в таблице много клиентов, сдвиг должен выполняться внутри клиента. Иначе последняя покупка Анны может стать предыдущей покупкой Бориса.

```python
events = pd.DataFrame({
    "client": [1, 1, 2, 2],
    "time": pd.to_datetime(["2026-01-01", "2026-01-03", "2026-01-02", "2026-01-04"]),
    "amount": [10, 30, 100, 200],
})
events = events.sort_values(["client", "time"])
events["previous"] = events.groupby("client")["amount"].shift(1)
print(events["previous"].tolist())   # [nan, 10.0, nan, 100.0]
```

При совпадающем времени может понадобиться дополнительный ключ порядка. Если порядок неизвестен, не придумывайте последовательность только ради работы функции.

`resample` агрегирует по календарным интервалам, например по дням. `asfreq` переиндексирует на заданную частоту без вычисления суммы. Заполнение отсутствующего дня нулём корректно только тогда, когда отсутствие строки означает отсутствие событий, а не сбой сбора.

## Соединение по последнему известному значению

Иногда признаки обновляются отдельно от событий: у клиента меняется тариф, а заказы поступают между обновлениями. `merge_asof` позволяет подобрать последнее известное значение по времени. Входы должны быть отсортированы, а направление и допустимый временной разрыв задаются явно.

Важно различать время события и время поступления данных. Поздно пришедший документ может описывать вчерашнее событие, но вчера система о нём ещё не знала. Честный исторический признак учитывает доступность информации, а не только дату внутри записи.

## Самопроверка и практика

1. Почему `rolling(7)` не всегда означает неделю?
2. Когда включение текущей строки создаёт утечку?
3. Почему историю нужно группировать по клиенту?
4. Чем отсутствие события отличается от отсутствия измерения?

Разбор: это семь строк; если текущее значение является неизвестной целью; иначе смешиваются независимые истории; ноль и неизвестность несут разные утверждения.

**Практика.** Удалите 2 января из первого набора и вычислите среднее двух предыдущих наблюдений. Для 4 января получится 20: использованы 1 и 3 января. Объясните, почему это не то же самое, что среднее за два предыдущих календарных дня.

В визуализации перемещайте момент прогноза и проверяйте, какие записи доступны слева от него. Далее соберём изученные операции в исследование данных.
