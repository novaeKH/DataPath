# pandas: таблица, индекс и выбор данных

В NumPy мы описывали таблицу через номера осей. В реальных данных удобнее обращаться к столбцам по именам: цена, город, дата. pandas добавляет именованные столбцы, индекс строк и операции с пропусками. Но имена влияют на вычисления: две серии складываются по меткам, а не просто по позиции.

Создадим маленькую таблицу заказов. Все дальнейшие действия в уроке используют именно её, поэтому пример можно выполнить сверху вниз.

## DataFrame и Series

```python
import pandas as pd

orders = pd.DataFrame({
    "order_id": [101, 102, 103, 104],
    "city": ["Казань", "Москва", "Казань", "Москва"],
    "amount": [100, 250, 150, 80],
})
print(orders.shape)   # (4, 3)
print(orders["amount"].tolist())   # [100, 250, 150, 80]
```

`DataFrame` — двумерная таблица. Столбец `orders["amount"]` — `Series`, одномерная последовательность значений с индексом. Выражение `orders[["amount"]]` возвращает таблицу из одного столбца: двойные скобки означают, что передан список имён столбцов.

По умолчанию строки имеют индекс 0, 1, 2, 3. Это метки pandas, а `order_id` пока обычный столбец. Индекс не следует автоматически считать уникальным идентификатором объекта: его уникальность нужно проверять отдельно.

## Метки и позиции — разные способы выбора

```python
indexed = orders.set_index("order_id")
print(indexed.loc[102, "amount"])   # 250
print(indexed.iloc[1, 1])           # 250
```

`loc` выбирает по меткам, `iloc` — по целочисленным позициям. После переноса `order_id` в индекс второй столбец — `amount`. `iloc[1, 1]` означает вторую строку и второй столбец, независимо от названий.

У среза `iloc[0:2]` правая граница исключена, как в Python. У среза по меткам `loc` правая метка обычно включается. Не смешивайте эти правила, особенно после фильтрации, когда индекс может выглядеть как `[0, 2]`.

## Фильтр — это серия логических значений

```python
mask = (orders["city"] == "Казань") & (orders["amount"] >= 120)
selected = orders.loc[mask, ["order_id", "amount"]]
print(selected.to_dict("records"))
# [{'order_id': 103, 'amount': 150}]
```

Каждое сравнение создаёт серию из `True` и `False`. Оператор `&` объединяет их поэлементно. Скобки обязательны из-за порядка операций. Обычные `and` и `or` работают с истинностью целого объекта и не заменяют поэлементные операции над сериями.

Фильтр не меняет исходную таблицу: он выбирает результат. Если нужно изменить значения в исходной таблице, выразите выбор и присваивание одной операцией:

```python
orders.loc[orders["city"] == "Казань", "amount"] = 200
print(orders["amount"].tolist())   # [200, 250, 200, 80]
```

Избегайте цепочки `orders[mask]["amount"] = ...`: она присваивает через промежуточный объект. В pandas 3 действует Copy-on-Write, и такое присваивание не обновляет исходную таблицу ожидаемым способом. Использование `loc` явно задаёт объект назначения.

## Индекс участвует в арифметике

```python
prices = pd.Series([100, 200], index=["a", "b"])
discounts = pd.Series([20, 10], index=["b", "a"])
print((prices - discounts).to_dict())
# {'a': 90, 'b': 180}
```

Для `a` вычитается 10, для `b` — 20. pandas сопоставляет метки. Если одна метка отсутствует во второй серии, результат может содержать пропуск. Это помогает корректно соединять данные, но удивляет, если вы рассчитывали на чисто позиционную арифметику.

Преобразование в NumPy через `to_numpy()` убирает метки. Делайте это только после проверки порядка строк и смысла столбцов.

## Типы, сортировка и новые признаки

`dtypes` показывает типы столбцов, `info()` — компактную сводку, `head()` — первые строки. Число, записанное строкой, не становится числом автоматически во всех операциях. Даты также требуют явного преобразования.

```python
orders["amount_with_fee"] = orders["amount"] + 10
ranked = orders.sort_values(["amount", "order_id"], ascending=[False, True])
print(ranked["order_id"].tolist())   # [102, 101, 103, 104]
```

Второй ключ сортировки делает порядок одинаковых сумм предсказуемым. Новое имя столбца показывает смысл преобразования. Если после сортировки нужен последовательный индекс, используйте `reset_index(drop=True)`; это меняет метки, но не должно удалять настоящий `order_id`.

Категориальный тип полезен для ограниченного набора повторяющихся значений. Он не превращает категорию в порядковое число по смыслу задачи: «Москва» не больше «Казани».

## Самопроверка и практика

1. Чем `orders["amount"]` отличается от `orders[["amount"]]`?
2. Почему `loc[102]` и `iloc[102]` означают разное?
3. Почему две серии с обратным порядком индекса не вычитаются строго по позиции?
4. Как изменить исходную таблицу после фильтрации?

Разбор: серия и таблица имеют разную размерность; один выбор использует метку, другой позицию; pandas выравнивает метки; следует использовать одно присваивание через `loc`.

**Практика.** На исходной таблице из начала урока выберите московские заказы дешевле 200. Ожидается заказ 104. Создайте столбец `is_large` для суммы не меньше 150; ожидаются `[False, True, True, False]`. Перед выполнением восстановите исходные данные, если меняли их в примерах.

В визуализации сопоставьте метки и позиции. Далее выясним, как работать с пропусками и некорректными значениями, не искажая смысл таблицы.
