# Очистка данных: сначала смысл, потом исправление

В таблице заказов есть пустая сумма, повторный идентификатор и отрицательное значение. Удалить всё подозрительное легко. Труднее понять, что именно произошло: повторная выгрузка, возврат денег, ошибка ввода или отсутствие измерения.

Очистка — набор решений о смысле данных. Хороший результат сохраняет объяснение каждого решения и позволяет проверить, какие записи изменились.

## Начинаем с единицы наблюдения

```python
import pandas as pd

raw = pd.DataFrame({
    "order_id": [101, 102, 102, 103, 104],
    "amount": ["100", "250", "250", "", "-20"],
    "city": ["Казань", "Москва", "Москва", None, "Казань"],
})
```

Если одна строка должна соответствовать одному заказу, повтор `order_id=102` требует проверки. Если строки обозначают отдельные платежи одного заказа, повтор может быть нормальным. Уникальность зависит от единицы наблюдения, которую также называют гранулярностью.

До изменения данных сохраните исходную таблицу. Затем проверьте число строк, пропуски, типы и дубликаты. Такой порядок позволяет объяснить разницу между исходным и очищенным набором.

## Преобразуем тип и измеряем потери

```python
clean = raw.copy()
clean["amount"] = pd.to_numeric(clean["amount"], errors="coerce")
print(clean["amount"].isna().tolist())
# [False, False, False, True, False]
```

`errors="coerce"` заменяет нераспознаваемое значение пропуском. Это полезно для диагностики, но не является окончательным решением: нужно посчитать, сколько новых пропусков появилось, и исследовать исходные строки.

Не используйте проверку `value == NaN`. Пропуски проверяют через `isna` и `notna`. Если числовой столбец должен хранить целые значения и пропуски, у pandas есть nullable-тип `Int64`; написание отличается от обычного NumPy-типа `int64`.

## Пропуск не равен нулю

Нулевая сумма может означать бесплатный заказ, а пропуск — неизвестную сумму. Заполнение пропуска нулём превращает незнание в утверждение.

Варианты зависят от задачи: восстановить значение из источника, исключить запись из конкретного расчёта, заполнить статистикой, добавить индикатор отсутствия или сохранить пропуск для модели, которая умеет с ним работать. Каждый вариант меняет предположения.

```python
clean["amount_missing"] = clean["amount"].isna()
print(clean["amount_missing"].sum())   # 1
```

Индикатор сохраняет информацию о факте отсутствия. Заполнение медианой может быть полезно для модели, но медиана должна вычисляться на обучающей части. Заполнение по всей таблице до разбиения передаёт информацию из проверки в обучение.

Пропуски могут возникать неслучайно. Если доход чаще скрывают клиенты с определёнными характеристиками, удаление таких строк изменит состав изучаемой группы.

## Дубликаты: полная строка и ключ

```python
print(clean.duplicated().sum())   # 1
clean = clean.drop_duplicates()
print(clean["order_id"].is_unique)   # True
print(len(clean))                   # 4
```

В данном примере повторяется целая строка, и по условию это повторная выгрузка. Удаление корректно. Но две строки с одним ключом и разными суммами нельзя разрешить произвольным `keep="first"`: нужно правило, например последняя подтверждённая версия по времени обновления.

После удаления проверьте не только число строк, но и агрегаты. Сумма может существенно измениться; это ожидаемо при устранении повторов, но требует объяснения.

## Выбросы и допустимые значения

В примере отрицательная сумма может быть возвратом. Замена её нулём уничтожит информацию о возврате. Сначала определите, хранит столбец цену заказа, платёж или изменение баланса.

Статистически необычное значение также не обязательно ошибочно. Большой заказ может быть редким, но реальным. Для анализа смотрите квантили, распределение по группам, источник и единицы измерения. Значение 10 000 иногда оказывается суммой в копейках среди рублей.

Обрезание по квантилям снижает влияние крайних значений, но меняет распределение. Если это часть предобработки ML, границы определяют на обучении и одинаково применяют к новым данным.

## Оформляем проверяемый результат

Вместо цепочки скрытых исправлений заведите понятные проверки: допустимый диапазон, уникальный ключ, обязательные поля, число удалённых строк. Не перезаписывайте исходный файл до проверки результата.

В нашем примере после удаления повтора осталось четыре заказа, один с неизвестной суммой. Отрицательная сумма сохранена до уточнения смысла. Это честнее, чем искусственно «идеальная» таблица без пропусков.

## Самопроверка и практика

1. Почему наличие повторного ключа ещё не доказывает ошибку?
2. Что потеряется при заполнении неизвестной суммы нулём?
3. Почему медиану нельзя вычислять на всей ML-выборке до разбиения?
4. Почему выброс нужно сначала исследовать?

Разбор: ключ зависит от гранулярности; неизвестное станет ложным наблюдением; параметры предобработки используют информацию проверки; редкое значение может быть настоящим событием.

**Практика.** Добавьте строку `{"order_id": 105, "amount": "ошибка", "city": "Москва"}`. После преобразования должны быть два пропуска суммы. Выведите исходные строки, которые не удалось преобразовать. Затем сформулируйте отдельно правило для повторной выгрузки и правило для возврата.

В визуализации сравните распределение до и после каждого решения. Следующий урок покажет, как соединять таблицы без размножения наблюдений.
