# Broadcasting: вычисления над совместимыми формами

У трёх объектов есть два признака. Нужно вычесть из каждого столбца его среднее. Вектор средних имеет форму `(2,)`, а таблица — `(3, 2)`. Почему NumPy разрешает их вычитание? И почему похожее действие с вектором из трёх чисел иногда приводит к ошибке или неверному смыслу?

Broadcasting — правило согласования форм при поэлементных операциях. Оно позволяет логически повторить значение вдоль оси без предварительного создания таблицы повторений.

## Сначала увидим нужное вычисление

```python
import numpy as np

X = np.array([[10., 100.], [20., 200.], [30., 300.]])
means = X.mean(axis=0)
centered = X - means
print(means)       # [20. 200.]
print(centered)
# [[ -10. -100.]
#  [   0.    0.]
#  [  10.  100.]]
```

Для первой строки получилось `[10-20, 100-200]`. Для второй — `[20-20, 200-200]`. Одна и та же пара средних применяется ко всем строкам.

Массив `means` не содержит три копии. NumPy использует форму, чтобы определить, какое значение нужно на каждой позиции результата. Сам результат при этом занимает память: отсутствие физического повторения входа не означает бесплатность вычисления.

## Правило сравнения справа налево

Формы сравниваются начиная с последней оси. Два размера совместимы, если равны или один из них равен единице. Недостающие слева оси рассматриваются как единицы.

Для `(3, 2)` и `(2,)` мысленно допишем вторую форму до `(1, 2)`. Справа размеры 2 и 2 равны. Слева 3 и 1 совместимы. Результат имеет форму `(3, 2)`.

Для `(3, 2)` и `(3,)` последними сравниваются 2 и 3. Они не равны и ни один не равен единице — операция невозможна. NumPy не угадывает, что три числа обозначают поправки для трёх строк.

## Явно задаём смысл оси

Если каждому объекту нужна своя поправка, представьте поправки столбцом:

```python
X = np.array([[10., 100.], [20., 200.], [30., 300.]])
offsets = np.array([1., 2., 3.])
print(X - offsets[:, None])
# [[  9.  99.]
#  [ 18. 198.]
#  [ 27. 297.]]
```

`offsets[:, None]` имеет форму `(3, 1)`: три строки и одна колонка. Теперь поправка каждой строки повторяется вдоль её признаков. `None` добавляет ось длины один; `np.newaxis` — другое имя того же приёма.

Особенно опасен квадратный массив. Если число строк равно числу признаков, неверный вектор может оказаться совместимым. Ошибки выполнения не будет, но поправки применятся по другой оси. Проверяйте смысл на маленьком несимметричном примере.

## Стандартизация и нулевая дисперсия

Чтобы признаки имели сопоставимый масштаб, из каждого значения вычитают среднее и делят на стандартное отклонение:

$$
z_{ij} = \frac{x_{ij} - \mu_j}{\sigma_j}.
$$

Индекс `i` обозначает объект, `j` — признак. Среднее `mu` и стандартное отклонение `sigma` вычисляются отдельно для каждого столбца. В результате единица выражает одно стандартное отклонение, а не исходный метр или рубль.

```python
X = np.array([[10., 5.], [20., 5.], [30., 5.]])
means = X.mean(axis=0, keepdims=True)
scales = X.std(axis=0, keepdims=True)
safe_scales = np.where(scales == 0, 1, scales)
Z = (X - means) / safe_scales
print(np.round(Z, 3))
# [[-1.225  0.   ]
#  [ 0.     0.   ]
#  [ 1.225  0.   ]]
```

Второй столбец постоянный. Деление на ноль не имеет смысла, поэтому используем масштаб 1: после вычитания среднего там и так нули. Для ML средние и масштабы определяют на обучающих данных и затем применяют к проверочным. Пересчитывать их на будущем входе нельзя.

## Внешняя операция и стоимость результата

Broadcasting позволяет вычислить все попарные разности:

```python
left = np.array([1, 4, 9])
right = np.array([2, 5])
differences = left[:, None] - right[None, :]
print(differences)
# [[-1 -4]
#  [ 2 -1]
#  [ 7  4]]
```

Результат имеет форму `(3, 2)`: каждая строка соответствует одному элементу `left`, каждый столбец — элементу `right`. При миллионе элементов в каждом входе такая таблица была бы слишком большой. Иногда вычисления нужно разбивать на блоки.

`np.tile` и `np.repeat` создают повторённые данные явно. Используйте их, когда нужна именно такая структура, а не просто совместимая арифметика.

## Самопроверка и практика

1. Какую форму даст сложение `(4, 1)` и `(1, 3)`?
2. Совместимы ли `(4, 3)` и `(4,)`?
3. Почему отсутствие ошибки не доказывает правильность выбранной оси?
4. Почему broadcasting способен привести к нехватке памяти?

Разбор: `(4, 3)`; нет, последние размеры различаются; смысл оси не хранится в форме; огромным может стать выходной массив.

**Практика.** Для таблицы `[[10, 20], [30, 40], [50, 60]]` прибавьте к строкам 1, 2 и 3, а затем умножьте первый столбец на 10 и второй на 100. Ожидается `[[110, 2100], [320, 4200], [530, 6300]]`. Перед запуском подпишите формы каждого промежуточного значения.

В визуализации меняйте размеры осей, объясняя совместимость справа налево. Дальше перейдём к pandas, где помимо формы есть ещё имена строк и столбцов.
