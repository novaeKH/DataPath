# 08. Декораторы и замыкания

## Функция как объект

В Python функцию можно сохранить в переменной, передать аргументом и вернуть из другой функции.

```python
def square(x: float) -> float:
    return x * x

operation = square
print(operation(3))
```

Это основа callback, декораторов и функционального стиля.

## Вложенная функция и замыкание

```python
def make_multiplier(factor: float):
    def multiply(value: float) -> float:
        return value * factor
    return multiply

double = make_multiplier(2)
print(double(5))  # 10
```

После завершения `make_multiplier` внутренняя функция продолжает помнить `factor`. Такая функция называется замыканием. Она хранит ссылки на переменные из enclosing scope, а не копии «на момент объявления» в общем случае.

## Позднее связывание

```python
functions = []
for i in range(3):
    functions.append(lambda: i)

print([fn() for fn in functions])  # [2, 2, 2]
```

`i` читается в момент вызова. Зафиксировать значение можно default-аргументом:

```python
functions.append(lambda i=i: i)
```

## Что делает декоратор

Декоратор принимает функцию и возвращает замену:

```python
def trace(func):
    def wrapper(*args, **kwargs):
        print(f"Вызов {func.__name__}")
        return func(*args, **kwargs)
    return wrapper

@trace
def predict(x: float) -> float:
    return x * 0.7
```

Синтаксис `@trace` эквивалентен `predict = trace(predict)`.

## Сохранение метаданных

Без `functools.wraps` имя, docstring и аннотации заменяются данными `wrapper`.

```python
from functools import wraps

def trace(func):
    @wraps(func)
    def wrapper(*args, **kwargs):
        print(f"Вызов {func.__name__}")
        return func(*args, **kwargs)
    return wrapper
```

## Декоратор с параметрами

Нужен ещё один уровень функции:

```python
from functools import wraps
from time import perf_counter


def repeat(times: int):
    if times < 1:
        raise ValueError("times должен быть положительным")

    def decorator(func):
        @wraps(func)
        def wrapper(*args, **kwargs):
            result = None
            for _ in range(times):
                result = func(*args, **kwargs)
            return result
        return wrapper
    return decorator
```

Порядок чтения: `repeat(3)` создаёт декоратор → декоратор получает функцию → wrapper вызывается вместо неё.

## Stateful closure

```python
def make_counter():
    count = 0

    def counter() -> int:
        nonlocal count
        count += 1
        return count

    return counter
```

`nonlocal` говорит, что присваивание должно менять переменную enclosing scope. Без него Python создаст локальную `count`.

## Применение в DS/ML

Декораторы полезны для:

- логирования вызовов;
- измерения времени;
- повторных попыток;
- проверки аргументов;
- кеширования чистых функций;
- регистрации обработчиков.

Но декоратор скрывает поток выполнения. Для сложной бизнес-логики явный вызов функции или context manager часто понятнее.

## Кеширование

```python
from functools import lru_cache

@lru_cache(maxsize=128)
def expensive_lookup(key: str) -> str:
    ...
```

Ключи должны быть hashable. Нельзя бездумно кешировать функции, зависящие от внешнего состояния, времени или изменяемых данных.

## Частые ошибки

- забыть `return func(...)`;
- не использовать `wraps`;
- потерять `*args` и `**kwargs`;
- декорировать async-функцию обычным wrapper;
- создать общий mutable state без синхронизации;
- использовать декоратор там, где он ухудшает читаемость;
- ожидать, что closure копирует все значения немедленно.

## Ответ интервьюеру

Замыкание — функция, которая сохраняет доступ к переменным внешней функции. Декоратор использует функции как объекты: принимает функцию и возвращает обёртку, поэтому `@decorator` заменяет исходный объект. Обычно я использую `functools.wraps`, сохраняю сигнатуру через `*args, **kwargs` и применяю декораторы только для сквозной логики вроде логирования, измерения времени или кеширования.
