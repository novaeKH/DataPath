# 02. List, tuple и string

[[01_Объекты_ссылки_и_изменяемость|← Предыдущий]] · [[03_Dict_Set_Hash_Map|Следующий →]]

## List как динамический массив

Список хранит непрерывный массив ссылок на объекты. Поэтому доступ по индексу — O(1). При `append` Python обычно заранее резервирует немного лишней ёмкости. Большинство добавлений дешёвые; редкое расширение копирует ссылки в больший буфер. Поэтому `append` — амортизированно O(1), но отдельный вызов может быть O(n).

Вставка в начало требует сдвинуть n ссылок:

```python
items.insert(0, value)  # O(n)
```

Для частых операций с двух концов используйте `collections.deque`.

### Добавление

```python
items = [1, 2]
items.append([3, 4])     # [1, 2, [3, 4]]
items.extend([5, 6])     # [1, 2, [3, 4], 5, 6]
items.insert(1, 99)      # вставка перед индексом 1
```

- `append(x)` добавляет один объект;
- `extend(iterable)` добавляет элементы iterable;
- `insert(i, x)` вставляет и сдвигает хвост.

### Удаление

- `remove(x)` удаляет первое равное значение, O(n), может дать `ValueError`;
- `pop()` удаляет и возвращает последний элемент, O(1);
- `pop(i)` удаляет по индексу, обычно O(n);
- `del items[i:j]` удаляет по индексу/срезу и ничего не возвращает.

## Tuple

Tuple — неизменяемая последовательность ссылок. Он обычно компактнее списка, подходит для фиксированной записи и может быть ключом словаря, если все его элементы hashable.

```python
point = (10, 20)
single = (10,)  # запятая создаёт tuple

record = ([1, 2], "train")
record[0].append(3)  # допустимо: tuple не заменён
```

## String

Строка — неизменяемая последовательность Unicode-символов. Индексация обычно O(1), срез длины k создаёт строку O(k).

```python
parts = ["data", "science", "interview"]
text = " ".join(parts)
```

Повторная конкатенация в цикле может многократно копировать растущую строку и приводить к O(n²) суммарной работе. Соберите части и вызовите `"".join(parts)` за линейное время относительно общего числа символов.

## `set` и `dict` в одном сравнении

Подробности — в [[03_Dict_Set_Hash_Map]].

| Операция | `list` | `tuple` | `str` | `set` | `dict` |
|---|---:|---:|---:|---:|---:|
| `x[i]` | O(1) | O(1) | O(1) | — | — |
| `x[a:b]`, длина k | O(k) | O(k) | O(k) | — | — |
| `value in x` | O(n) | O(n) | O(n·m) в общем случае | O(1) среднее | O(1) среднее по ключу |
| добавить в конец | O(1) аморт. | — | — | O(1) среднее | O(1) среднее |
| вставить/удалить в начале | O(n) | — | — | O(1) среднее | O(1) среднее |
| сортировка | O(n log n) | через `sorted` | через `sorted` | через `sorted` | через `sorted` |
| память | ссылки + запас | ссылки | символы | хеш-таблица | ключи + значения + таблица |

`substring in text` зависит от длины строки и подстроки; на собеседовании безопасно не называть это O(1).

## Порядок

- `list`, `tuple`, `str` упорядочены;
- `dict` гарантированно сохраняет порядок вставки в Python 3.7+;
- `set` не обещает пользовательский порядок, даже если конкретный запуск выглядит стабильным.

Порядок `dict` не превращает его в структуру для быстрого доступа по «номеру позиции».

## Сортировка и ключ

```python
rows = [("a", 3), ("b", 1)]
ordered = sorted(rows, key=lambda row: row[1])
assert ordered == [("b", 1), ("a", 3)]
```

`sorted(iterable)` возвращает новый список. `list.sort()` меняет список и возвращает `None`. Сортировка Python стабильна: равные по ключу элементы сохраняют относительный порядок.

## Предскажите результат

```python
items = [1, 2]
result = items.append(3)
print(items, result)

letters = ["a"]
letters.extend("bc")
print(letters)

values = [3, 1, 2]
print(values.sort())
```

<details>
<summary>Ответы</summary>

`[1, 2, 3] None`; `["a", "b", "c"]`; `None` (а `values` стал `[1, 2, 3]`).

</details>

## Что сказать интервьюеру

> List — динамический массив ссылок: индекс O(1), append амортизированно O(1), вставка в начало O(n) из-за сдвига. Tuple и str неизменяемы. Повторную сборку строк лучше делать через `join`. Membership в list линейный, а в set/dict — O(1) в среднем благодаря хеш-таблице.

## Мини-контрольная

1. Почему `append` не гарантированно O(1) для каждого вызова?
2. Чем `append` отличается от `extend`?
3. Почему `pop(0)` медленный?
4. Может ли tuple быть ключом, если внутри list?
5. Чем `sort` отличается от `sorted`?

<details>
<summary>Ответы</summary>

1. Иногда нужен resize. 2. Один объект против элементов iterable. 3. Сдвигается хвост. 4. Нет. 5. In-place и `None` против нового списка.

</details>
