# Итоговый кейс — Спрос на велосипеды и линейная регрессия

> [!case] Бизнес-задача
> Городская служба проката хочет заранее оценивать число аренд на каждый час, чтобы перемещать велосипеды между станциями и планировать дежурства. Одна строка — один час. Целевая переменная `cnt` — число аренд за этот час. Прогноз должен быть готов **до начала часа**.

Кейс использует [UCI Bike Sharing](https://archive.ics.uci.edu/dataset/275/bike+sharing+dataset): 17 389 часовых наблюдений Capital Bikeshare за 2011–2012 годы. Источник: UCI Machine Learning Repository, DOI `10.24432/C5W894`, лицензия CC BY 4.0.

Большой файл не хранится в репозитории. Можно загрузить архив со страницы UCI и положить `hour.csv` в:

```text
data/external/bike-sharing/hour.csv
```

Или получить данные программно:

```python
# pip install ucimlrepo
from ucimlrepo import fetch_ucirepo

bike_sharing = fetch_ucirepo(id=275)
X_raw = bike_sharing.data.features.copy()
y_raw = bike_sharing.data.targets.copy()
```

## Готовность перед кейсом

- Обязательно: таблицы и признаки, честное разбиение, Linear Regression, MAE/MSE/RMSE.
- Рекомендуется: очистка данных, `ColumnTransformer`, `Pipeline`.
- Можно изучить после: регуляризация и более гибкие модели.

Кейс не блокирует запуск, если рекомендованные темы ещё не завершены: в guided-режиме подсказки возвращают к нужному шагу.

## Этап 0. До просмотра данных

Запишите собственные ожидания. Что может оказаться проблемой?

- пропущенные значения;
- дубликаты;
- технические идентификаторы;
- признаки, доступные только после момента прогноза;
- числа, которые на самом деле кодируют категории;
- временная зависимость;
- выбросы и редкие режимы;
- изменение спроса между 2011 и 2012 годами.

Не пытайтесь заранее угадать «правильные галочки». Цель — сформировать проверяемые гипотезы.

## Этап 1. Аудит данных

До `fit()` получите минимальный профиль:

```python
import pandas as pd

df = pd.read_csv(
    "data/external/bike-sharing/hour.csv",
    parse_dates=["dteday"],
)

print(df.shape)
print(df.head())
print(df.dtypes)
print(df.isna().sum().sort_values(ascending=False).head(10))
print("duplicates:", df.duplicated().sum())
print(df["cnt"].describe())
```

Затем проверьте:

1. уникальность `instant`;
2. диапазоны `hr`, `weekday`, `season`, `weathersit`, `temp`, `hum` и `windspeed`;
3. равенство `cnt == casual + registered`;
4. порядок `dteday` и `hr`;
5. распределение цели и редкие погодные состояния;
6. связь `temp` и `atemp`.

Отсутствие пропусков не означает, что данные готовы к модели. Утечка, неверный смысл типа и нечестное разбиение опаснее пустой ячейки.

## Этап 2. Найдите утечку до обучения

UCI определяет:

```text
cnt = casual + registered
```

Число случайных и зарегистрированных аренд становится известно после завершения часа. Если передать `casual` и `registered` во вход модели, она почти напрямую восстановит целевую переменную.

Для прогноза до начала часа исключите:

```python
leakage_columns = ["casual", "registered"]
technical_columns = ["instant"]
```

`instant` не является прямой утечкой цели, но это технический номер записи и скрытый указатель времени. Настоящую временную информацию лучше извлекать явно и оценивать на будущем периоде.

## Этап 3. Разделите прошлое и будущее

Создайте временную метку:

```python
df["timestamp"] = df["dteday"] + pd.to_timedelta(df["hr"], unit="h")
df = df.sort_values("timestamp").reset_index(drop=True)
```

Первый честный вариант — последние 20% часов оставить для теста:

```python
cutoff = int(len(df) * 0.8)
train = df.iloc[:cutoff].copy()
test = df.iloc[cutoff:].copy()
```

Случайное перемешивание отвечает на более лёгкий вопрос: сможет ли модель предсказывать случайно спрятанный час из того же временного диапазона. Реальное применение требует переноса из прошлого в будущее.

## Этап 4. Сначала простая базовая модель

До Linear Regression предскажите среднее обучающей части:

```python
import numpy as np

mean_prediction = np.full(len(test), train["cnt"].mean())
```

Базовая модель нужна не для красоты. Без неё непонятно, извлекла ли Linear Regression полезный сигнал или только выглядит сложнее.

Не используйте среднее тестовой части: оно недоступно в момент построения прогноза и даёт нечестное преимущество.

## Этап 5. Linear Regression в Pipeline

Признаки `season`, `mnth`, `hr`, `weekday` и `weathersit` записаны числами, но кодируют категории. Если оставить их обычными числами, модель навяжет линейный порядок: например, разница между часами `22` и `23` станет такой же, как между `1` и `2`.

```python
from sklearn.compose import ColumnTransformer
from sklearn.linear_model import LinearRegression
from sklearn.pipeline import Pipeline
from sklearn.preprocessing import OneHotEncoder, StandardScaler

categorical = ["season", "mnth", "hr", "holiday", "weekday", "workingday", "weathersit"]
numeric = ["yr", "temp", "atemp", "hum", "windspeed"]

preprocess = ColumnTransformer(
    [
        ("cat", OneHotEncoder(handle_unknown="ignore"), categorical),
        ("num", StandardScaler(), numeric),
    ]
)

model = Pipeline(
    [
        ("preprocess", preprocess),
        ("regressor", LinearRegression()),
    ]
)

model.fit(train[categorical + numeric], train["cnt"])
prediction = model.predict(test[categorical + numeric])
```

`StandardScaler` здесь не является обязательным условием OLS. Он оставлен как совместимый шаг для дальнейшего сравнения с Ridge и помогает держать числовые признаки в сопоставимом масштабе.

## Этап 6. Оценка без коллекции лишних метрик

```python
from sklearn.metrics import (
    mean_absolute_error,
    mean_squared_error,
    r2_score,
)


def regression_report(y_true, y_pred):
    mse = mean_squared_error(y_true, y_pred)
    return {
        "MAE": mean_absolute_error(y_true, y_pred),
        "MSE": mse,
        "RMSE": mse ** 0.5,
        "R2": r2_score(y_true, y_pred),
    }


print("mean:", regression_report(test["cnt"], mean_prediction))
print("linear:", regression_report(test["cnt"], prediction))
```

Интерпретируйте числа:

- MAE — типичный модуль промаха в числе аренд;
- MSE — квадрат аренд, поэтому сама величина хуже читается;
- RMSE снова измеряется в арендах и сильнее выделяет крупные промахи;
- \(R^2\) сравнивает объяснённую вариативность с прогнозом среднего.

Не выбирайте модель только по одной цифре. Сравните её с базовой моделью и проверьте, где происходят ошибки.

## Этап 7. Анализ ошибок

```python
errors = test[["timestamp", "hr", "workingday", "weathersit", "season", "cnt"]].copy()
errors["prediction"] = prediction
errors["residual"] = errors["cnt"] - errors["prediction"]
errors["abs_error"] = errors["residual"].abs()

print(errors.nlargest(20, "abs_error"))
print(errors.groupby("hr")["residual"].agg(["mean", "median", "count"]))
print(errors.groupby("weathersit")["abs_error"].mean())
```

Ответьте до чтения эталонного разбора:

1. В какие часы модель чаще занижает спрос?
2. Есть ли отдельный режим рабочих дней?
3. Сосредоточены ли большие ошибки в редкой погоде?
4. Ухудшается ли качество в более позднем году?
5. Похож ли рисунок ошибок на нелинейность?

Кейс не заканчивается строкой `RMSE = ...`. Если утренние и вечерние пики постоянно недооценены, это конкретное направление улучшения: представление времени, взаимодействия или более гибкая модель на том же временном разбиении.

## Что нужно сдать

- временное разбиение;
- метрики средней базовой модели и Linear Regression;
- таблицу или график крупнейших ошибок;
- три гипотезы о причинах систематических промахов;

## Критерий завершения

Решение завершено, когда эксперимент воспроизводим, утечка исключена, будущее не попало в обучение, Linear Regression честно сравнена с прогнозом среднего, а крупнейшие ошибки разобраны по реальным сегментам.
