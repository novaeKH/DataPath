# Как решать задачи на собеседовании

[[01_План_подготовки|← План]] · [[01_Объекты_ссылки_и_изменяемость|Python Core →]]

## Рабочий протокол

### 1. Уточнить контракт

Скажите вслух: «Я правильно понял: дано …, нужно вернуть …? Вход может быть пустым? Есть ли дубликаты? Можно ли менять вход?»

Не начинайте с кода, пока не понятны тип результата, ограничения и крайние случаи.

### 2. Назвать brute force

Brute force показывает, что вы поняли задачу. Коротко опишите перебор и оцените его. Затем найдите повторную работу:

- многократно ищем «видел ли элемент» → `set`/`dict`;
- считаем один диапазон снова и снова → Prefix Sum или Sliding Window;
- сортированный вход → Two Pointers или Binary Search;
- каждый раз ищем лучший из многих → heap;
- ближайший уровень/минимум шагов → BFS.

### 3. Выбрать шаблон через пять вопросов

1. Какой сигнал есть в условии?
2. Что нужно хранить?
3. Какое утверждение остаётся истинным после каждого шага — инвариант?
4. Что меняет состояние?
5. Почему каждый элемент обрабатывается ограниченное число раз?

### 4. Проговорить решение до кода

Пример:

> Иду слева направо и храню в словаре число → индекс. Для текущего `x` проверяю, встречалось ли `target - x`. Если да, пара найдена; если нет, запоминаю `x`. Инвариант: словарь содержит только уже просмотренные элементы. Каждый элемент обрабатывается один раз, поэтому среднее время O(n), память O(n).

### 5. Написать код маленькими проверяемыми частями

Используйте читаемые имена, type hints и ранние возвраты. Комментарий нужен для причины, а не для пересказа строки.

```python
def two_sum(nums: list[int], target: int) -> tuple[int, int] | None:
    index_by_value: dict[int, int] = {}
    for index, value in enumerate(nums):
        complement = target - value
        if complement in index_by_value:
            return index_by_value[complement], index
        index_by_value[value] = index
    return None
```

### 6. Проверить вручную

Минимум четыре случая:

- обычный;
- пустой или минимальный;
- дубликаты;
- ответ в начале/конце или ответа нет.

Трассируйте только ключевое состояние:

| `index` | `value` | `complement` | словарь до шага | действие |
|---:|---:|---:|---|---|
| 0 | 2 | 7 | `{}` | сохранить `2: 0` |
| 1 | 7 | 2 | `{2: 0}` | вернуть `(0, 1)` |

## Фраза, если вы застряли

> Сначала зафиксирую корректный полный перебор, затем посмотрю, какую работу он повторяет. Сейчас повторяется поиск …; попробую хранить это состояние в …

Это лучше молчаливого перебора вариантов.

## Частые промахи

- назвать сложность до определения размера входа;
- писать решение, не уточнив, можно ли менять массив;
- обещать O(1) памяти, создавая срез или нормализованную строку;
- забыть, что `sort()` меняет список и возвращает `None`;
- не сформулировать условие сдвига левой границы;
- использовать `if`, когда нарушение окна нужно устранять многократно;
- завершить после успешного примера, не проверив пустой вход.
