# Mock Interview

[[Code_Review_задачи|← Code Review]] · [[00_Главная_страница|Главная]]

Проводите без открытых решений. На теорию — короткий ответ, затем follow-up. На задачу — сначала контракт и brute force. Запишите себя голосом.

## Шкала оценки

| Балл | Уровень |
|---:|---|
| 0 | не знаю |
| 1 | знаю определение |
| 2 | могу привести пример |
| 3 | могу объяснить внутреннюю логику |
| 4 | могу применить в новой задаче |

Для каждого вопроса/задачи ставьте 0–4. Готовность: среднее ≥3, ни одной обязательной темы на 0, задача решена с тестами и объяснением.

## Mock Interview 1

Уровень: начинающий DS intern. Рекомендуемый формат: 5 блоков.

### Блок A — 10 вопросов по Python

1. `is` и `==`.
2. Mutable/immutable и общий список.
3. Shallow/deep copy.
4. Почему `append` амортизированно O(1)?
5. `set` против `dict`.
6. Почему list не hashable?
7. Mutable default.
8. Iterable против iterator.
9. Почему generator одноразовый?
10. `sort()` против `sorted()`.

**Хороший ответ:** определение + маленький пример + одно ограничение. Ожидаемые тезисы — в [[Python_вопросы#Обязательный минимум]].

### Блок B — задача 1

Дан список category IDs. Верните первый ID, встретившийся второй раз, иначе `None`.

Примеры: `[3,1,4,1,5] → 1`; `[1,2,3] → None`.

Ожидается: brute O(n²), set O(n) среднее/O(n), инвариант seen-префикса, пустой ввод.

### Блок C — задача 2

Дана строка; найдите длину максимального непрерывного фрагмента без повторяющихся символов.

Ожидается: [[03_Sliding_Window_задачи#LC 3 — Longest Substring Without Repeating Characters]], объяснение `right-left+1`, O(n).

### Блок D — code review

Используйте [[Code_Review_задачи#CR 1 — Mutable default]]. Дополнительный вопрос: как это проявится в переиспользуемом feature builder?

### Блок E — сложность

- два последовательных прохода;
- `x in list` внутри прохода;
- set membership;
- срез `nums[:]`;
- Sliding Window с монотонным left.

### Критерии

- 10 Python-вопросов: 40 баллов;
- две задачи: по 20;
- review: 10;
- сложность и коммуникация: 10.

**Интерпретация:** 80+ — переходите к Mock 2; 60–79 — повторите слабые темы; <60 — вернитесь к дням 1–4 плана.

## Mock Interview 2

Уровень: уверенный junior.

### Блок A — углублённые вопросы

1. Почему dict O(1) только в среднем?
2. Контракт `__eq__`/`__hash__`.
3. Что происходит внутри `for`?
4. Как generator хранит состояние?
5. MRO и `super()`.
6. `__repr__`, `__str__`, `__call__`, `__contains__`.
7. Reference counting и цикл.
8. GIL: IO-bound vs CPU-bound.
9. Почему NumPy быстрее Python-цикла?
10. Type hints: `Iterable` vs `Sequence`.

Ожидается ответ 1–2 минуты с ограничениями, не только определение.

### Блок B — выбор шаблона

Для каждого условия выберите подход и отвергните альтернативу:

1. много сумм по неизменяемым диапазонам;
2. самый короткий положительный подмассив с суммой ≥ target;
3. k самых частых событий в большом потоке;
4. кратчайшее число рёбер до узла;
5. пара с target в отсортированном массиве.

Ожидается: Prefix Sum; Sliding Window; Counter + heap; BFS; Two Pointers.

### Блок C — Medium

Решите LC 560 [[04_Prefix_Sum_задачи#LC 560 — Subarray Sum Equals K]].

Обязательные точки:

- объяснить, почему Sliding Window не подходит с отрицательными;
- вывести `previous_prefix = current_prefix - k`;
- начать map с `{0:1}`;
- время O(n) среднее, память O(n);
- тесты `[1,1,1],2`, `[1,-1,0],0`, пустой список.

### Блок D — компромисс времени и памяти

Сравните решения Intersection of Two Arrays II:

- Counter O(n+m) время, O(min(n,m)) память;
- сортировка + Two Pointers O(n log n + m log m), O(1) дополнительной памяти при разрешённой in-place сортировке.

Назовите, как изменится выбор, если массивы уже отсортированы или один слишком велик и хранится на диске.

### Блок E — Python design question

Спроектируйте источник батчей для ML pipeline:

```python
class BatchSource:
    def __iter__(self) -> Iterator[list[Record]]:
        ...
```

Обсудите:

- iterable, создающий новый iterator, или одноразовый iterator;
- закрытие файла;
- размер батча и последний неполный batch;
- ошибки парсинга;
- type hints;
- повторный проход;
- тестируемость и метрики.

Хорошее решение отделяет открытие ресурса от обработки, явно описывает одноразовость или создаёт новый generator в `__iter__`, использует `with`, не загружает весь файл.

### Критерии

- теория: 30;
- выбор шаблона: 20;
- Medium: 30;
- trade-off: 10;
- design: 10.

**Готовность:** 75+ и Medium без полного решения; иначе составьте список из трёх ошибок и назначьте повтор +1/+3/+7.
