# Алгоритмические вопросы

[[Python_вопросы|← Python]] · [[Code_Review_задачи|Code Review →]]

## Обязательный минимум

| Вопрос | Хороший короткий ответ | Follow-up |
|---|---|---|
| Что такое инвариант? | Утверждение, истинное после каждой итерации; оно связывает код с корректностью | Инвариант Two Sum/Sliding Window |
| Почему два последовательных цикла O(n)? | O(n)+O(n)=O(2n)=O(n) | Когда два цикла дают O(n²)? |
| Почему Sliding Window O(n) с внутренним while? | Каждый элемент входит и выходит максимум раз | Когда условие окна немонотонно? |
| Hash Map или Two Pointers для Two Sum? | Map для неотсортированного O(n)/O(n); pointers для sorted O(n)/O(1) | Можно ли сортировать, если нужны исходные индексы? |
| Sliding Window или Prefix Sum? | Движущееся валидное окно vs range queries/суммы с отрицательными | LC 560 почему map? |
| BFS или DFS? | BFS — уровни/минимум рёбер, DFS — поддеревья/компоненты | Память O(w) vs O(h) |
| Heap или sorting? | Малый Top-K/поток — heap O(n log k); полный порядок — sort | Один максимум? |
| Greedy или DP? | Greedy требует безопасного локального выбора; DP сравнивает состояния | Контрпример coin change |
| Почему Binary Search O(log n)? | Диапазон кандидатов делится пополам | Какой предикат монотонен? |
| Что считать дополнительной памятью? | Структуры алгоритма сверх входа; результат обычно оговаривается отдельно | Recursion stack? |

## Как выбирать структуру

1. «Уже видел?» → set.
2. «Сколько/где?» → dict.
3. «Последний незакрытый?» → stack.
4. «Первый пришёл — первый ушёл?» → queue/deque.
5. «Лучший k/экстремум многократно?» → heap.
6. «Индекс и случайный доступ?» → list.

## Вопросы на доказательство

### Почему движение короткой линии в LC 11 безопасно?

Текущая площадь ограничена меньшей высотой. Движение большей линии уменьшает ширину, не улучшая нижнюю границу высоты; улучшение возможно только после замены короткой.

### Почему LC 128 с внутренним while ожидаемо O(n)?

Цепь расширяется только от значения, у которого нет predecessor. Каждый уникальный элемент входит в расширение одной цепи.

### Почему mark-on-enqueue важен в BFS?

Иначе одну вершину могут добавить несколько родителей до первого извлечения, увеличивая queue и повторную работу.

### Почему `max_frequency` в LC 424 можно не уменьшать?

Он остаётся верхней границей лучшей частоты, увиденной для рассматриваемых правых границ. Это может оставить окно формально «слишком широким» для текущих counts, но не создаёт невозможный новый максимум: длина фиксируется только относительно достижимого historical max.

## Уверенный junior

- Объясните амортизированную O(1) queue на двух stacks.
- Сравните iterative и recursive DFS.
- Что изменится в Binary Search с дубликатами?
- Почему heapify O(n), а не O(n log n)?
- Когда Prefix Sum недостаточен из-за обновлений?
- Как считать сложность Backtracking с копированием результата?
- Почему stable sorting полезна?
- Чем closed interval отличается от half-open в merge/meeting задачах?

## Антишаблоны в ответах

- «Два указателя быстрее» без условия движения.
- «Dict всегда O(1)».
- «Вложенный цикл всегда O(n²)».
- «DP — когда есть рекурсия».
- «BFS быстрее DFS».
- «O(1) памяти», когда создан set/slice/normalized string.
