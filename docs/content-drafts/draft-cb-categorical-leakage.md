## Почему обычный target encoding «подглядывает» (дополнение)

**Задача:** предсказать отток клиента ($y=1$ — ушёл). Признак: город.

**Данные (6 клиентов, упорядочены по времени):**

| # | Город | Ушёл ($y$) |
|---|---|---|
| 1 | Москва | 0 |
| 2 | Питер | 1 |
| 3 | Москва | 1 |
| 4 | Питер | 0 |
| 5 | Москва | 0 |
| 6 | Питер | 1 |

**Наивный target encoding (ошибка):**
Для каждого клиента считаем средний $y$ по городу, включая ЕГО СОБСТВЕННЫЙ ответ:
- Москва: $(0 + 1 + 0) / 3 = 0.33$
- Питер: $(1 + 0 + 1) / 3 = 0.67$

**Проблема:** target encoding «видит» ответ, который пытается предсказать.
Например, клиент #3 (Москва, $y=1$) получает encoding 0.33,
который включает его собственный $y=1$ — модель учится на утёкшей информации.
Это **data leakage**.

**Правильный ordered target statistic (CatBoost):**
Используем искусственный порядок (например, время). Для клиента $i$
encoding считается только по клиентам ДО него:

| # | Город | $y$ | Ordered TS | Пояснение |
|---|---|---|---|---|
| 1 | Москва | 0 | 0.5 (prior) | Нет предыдущих — prior |
| 2 | Питер | 1 | 0.5 (prior) | Нет предыдущих — prior |
| 3 | Москва | 1 | 0.0 | Только клиент #1 до него: 0/1 = 0 |
| 4 | Питер | 0 | 1.0 | Только клиент #2 до него: 1/1 = 1 |
| 5 | Москва | 0 | 0.5 | Клиенты #1, #3: (0+1)/2 = 0.5 |
| 6 | Питер | 1 | 0.5 | Клиенты #2, #4: (1+0)/2 = 0.5 |

**Почему это работает:**
- Ordered TS не использует собственный $y_i$ объекта → нет leakage.
- Prior (0.5 по умолчанию) сглаживает оценки для редких категорий.
- При повторном обучении используется случайная перестановка (permutation) —
  это дополнительно снижает зависимость от порядка.

**Примечание для ручной проверки:**
- Согласовать обозначения с формулами в основной заметке ($\operatorname{TS}_i$, prior, smoothing).
- Добавить перекрёстную ссылку на «типичные ошибки» (target leakage).
