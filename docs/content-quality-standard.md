# DataPath — Content Quality Standard (Фаза 6A)

Критерии качества учебных материалов по уровням: Minimum, Solid, Reference-quality.

## Уровни контента

### Minimum — минимально пригодная заметка

- Корректное определение темы (без фактических ошибок);
- Краткая интуиция («зачем это нужно»);
- Хотя бы один конкретный пример;
- Связи со смежными темами (wiki-ссылки);
- Указаны skills;
- Отсутствие критических ошибок (битые ссылки, formulas с ошибками).

**Признаки:** заметка готова к использованию в уроке, но может требовать
дополнительного объяснения от наставника.

### Solid — хорошая учебная заметка

Всё из Minimum плюс:

- Мотивация: практическая задача, которую решает метод;
- Интуиция: простое объяснение без формул;
- Механизм: пошаговое описание алгоритма;
- Необходимая математика (с расшифровкой обозначений);
- Конкретный пример с числами;
- Гиперпараметры и их влияние;
- Типичные ошибки и как их избежать;
- Практика или checkpoint;
- Сравнение с соседними методами (когда релевантно).

**Признаки:** заметка самодостаточна для самостоятельного изучения.

### Reference-quality — эталонная заметка

Всё из Solid плюс:

- Связное глубокое объяснение (несколько уровней детализации);
- Качественная визуализация (график, схема, diagram);
- Рабочий код (скопировал → запустил → получил результат);
- Математическая интерпретация (связь с теорией вероятностей/оптимизацией);
- Реальные ограничения метода (когда НЕ применять);
- Сравнение нескольких моделей/подходов в таблице;
- Практика с автоматической проверкой;
- Review-вопросы для интервального повторения;
- Case (реалистичный сценарий применения);
- Короткий ответ для собеседования (3–5 предложений);
- Хорошая структура для RAG (самодостаточные секции, минимум местоимений).

## Рекомендуемые блоки заметки

Не все 13 блоков обязательны для каждой заметки. Выбор зависит от типа материала
(concept — полный набор; deep-dive — математика + код; interview — краткий ответ).

1. **Зачем тема нужна** (motivation) — практическая задача.
2. **Интуиция** (intuition) — простое объяснение.
3. **Как работает по шагам** (mechanism) — алгоритм.
4. **Необходимая математика** (mathematics) — формулы с расшифровкой.
5. **Маленький пример** (example) — конкретные числа.
6. **Визуализация** (visualization) — график или схема.
7. **Код** (code) — минимальный работающий пример.
8. **Гиперпараметры** (hyperparameters) — таблица с эффектами.
9. **Типичные ошибки** (pitfalls) — что может пойти не так.
10. **Сравнение** (comparison) — таблица альтернатив.
11. **Checkpoint** — вопросы для самопроверки.
12. **Лаборатория или практика** (lab) — интерактивное упражнение.
13. **Ответ для собеседования** (interview_summary) — 3–5 предложений.

## Статусы source_heading (Фаза 6A)

Каждый запрошенный в datapath `source_heading` разрешается в один из статусов:

- `exact` — заголовок точно совпадает с H2 source-заметки;
- `normalized` — совпадает после нормализации (trim, регистр, markdown-эмфазис,
  числовые префиксы); отбор секций использует нормализованное сопоставление;
- `fallback` — заголовок не найден; берутся все секции по порядку. Аудит
  показывает warning `source_heading_fallback` (это не ошибка сборки);
- `missing` — source-заметка недоступна или пуста. Аудит показывает warning
  `source_heading_missing`.

Warnings не дают ненулевой exit code quality CLI; ненулевой exit code дают
только errors (битый content_path, path traversal, пустой урок, parser crash).
Цель статусов — сделать несовпадение заголовков видимым, а не прятать его.

## Критерии пригодности для RAG

Для качественного retrieval каждая заметка должна:

- Содержать **одну каноническую тему** или явно обозначенную структуру;
- Иметь **понятные H2/H3-заголовки**, отражающие содержание секции;
- Содержать **самодостаточные секции** (понятные без чтения всей заметки);
- **Расшифровывать обозначения** при первом использовании;
- Минимизировать **местоимения без контекста** («он», «этот метод» — неясно какой);
- Избегать **ненужного дублирования** между заметками;
- Иметь **корректные wiki-ссылки** на связанные темы;
- Использовать **стабильные content IDs** (не менять после assign);
- Явно указывать связь со **skills** в frontmatter.
