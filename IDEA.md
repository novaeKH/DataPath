# DataPath — интерактивная платформа для изучения Data Science

## 1. Идея проекта

Создать современное русскоязычное приложение для последовательного, практического и персонализированного изучения Data Science.

DataPath — это не библиотека статей, не каталог видеокурсов и не набор разрозненных тестов. Приложение должно формировать персональный маршрут обучения, показывать связи между темами, запоминать сильные и слабые стороны пользователя и адаптировать дальнейшее обучение на основе его результатов.

Основной принцип:

> Пользователь не просто проходит уроки. Он постепенно строит собственную карту знаний, применяет темы в связанных задачах, получает персональные рекомендации и закрепляет знания в реальных проектах.

Приложение должно сочетать:

- интерактивные курсы;
- визуальную карту знаний;
- практические упражнения;
- мини-кейсы по связанным темам;
- интеграционные кейсы по крупным модулям;
- смешанные кейсы по всем изученным направлениям;
- систему интервального повторения;
- персональную модель знаний;
- AI-наставника на основе RAG;
- подготовку к техническим собеседованиям;
- полноценные учебные проекты.

---

## 2. Цель продукта

Главная цель DataPath — убрать хаос из обучения Data Science.

Пользователь не должен самостоятельно решать:

- что изучать сегодня;
- какую тему повторить;
- какие знания уже закреплены;
- где находятся пробелы;
- к какому проекту перейти;
- какие темы связаны между собой;
- насколько он готов к собеседованию или практической задаче.

Приложение должно каждый раз предлагать один понятный следующий шаг и объяснять, почему он выбран.

---

## 3. Основной пользовательский цикл

Главный цикл обучения:

```text
Изучение темы
    ↓
Интерактивные упражнения
    ↓
Проверка понимания
    ↓
Мини-кейс по связанным темам
    ↓
Обнаружение пробелов
    ↓
Обновление карты знаний
    ↓
Добавление слабых элементов в повторение
    ↓
Рекомендация следующего шага
    ↓
Применение знаний в более крупном кейсе или проекте
```

Система должна связывать обучение, повторение, практику и проекты в единый процесс.

---

## 4. Главный экран «Сегодня»

После запуска пользователь видит персональный экран, а не каталог курсов.

Пример:

```text
Добрый вечер, Илья

Главная задача на сегодня:
Продолжить Gradient Boosting — урок 4 из 7

Рекомендуемая сессия — 25 минут:
• 10 минут — новый материал;
• 5 минут — повторение Precision и Recall;
• 10 минут — практическая задача по CatBoost.

Нужно усилить:
SQL JOIN, PCA, backpropagation

Сильные темы:
Decision Tree, Random Forest, train/test split
```

На главном экране должны находиться крупные спокойные карточки:

- продолжить обучение;
- короткая практика;
- повторить слабые темы;
- текущий мини-кейс;
- текущий проект;
- спросить AI-наставника;
- прогресс за неделю.

На экране не должно быть десяти графиков и большого количества статистики.

В каждый момент показывается:

1. главное действие;
2. краткое объяснение, почему оно выбрано;
3. несколько дополнительных вариантов.

## 5. Визуальная концепция

### 5.1. Общий стиль

Интерфейс должен выглядеть современно, спокойно и дорого, но не перегруженно.

Визуальное направление:

## Quiet Spatial Learning

Это пространственный образовательный интерфейс, в котором темы, курсы, кейсы и проекты ощущаются как части единой среды.

Основные принципы:

- много свободного пространства;
- один главный объект на экране;
- крупная читаемая типографика;
- мягкая глубина вместо тяжёлых рамок;
- спокойные поверхности;
- плавные переходы между экранами;
- минимум постоянных панелей;
- постепенное раскрытие деталей;
- цвет используется для смысла, а не для украшения;
- интерфейс остаётся понятным даже при большом количестве контента.

Не использовать:

- большое количество неоновых градиентов;
- десятки разноцветных карточек;
- тяжёлое стекло и постоянный blur;
- перегруженные дашборды;
- слишком детскую геймификацию;
- хаотичные графы с сотнями подписей;
- бесконечные списки уроков;
- тяжёлые 3D-эффекты;
- декоративные элементы, которые не помогают обучению.

### 5.2. Цветовая система

У приложения должны быть светлая и тёмная темы.

Базовый интерфейс остаётся нейтральным:

- тёплый светлый фон или глубокий графитовый фон;
- спокойные серые поверхности;
- высокий контраст текста;
- мягкие тени;
- тонкие границы;
- минимум ярких акцентов.

Каждому направлению соответствует свой акцент:

- Python — мягкий сине-жёлтый;
- SQL — холодный голубой;
- математика — фиолетовый;
- классический ML — зелёный;
- Deep Learning — коралловый;
- NLP и LLM — сиреневый;
- MLOps — бирюзовый.

На одном экране должен доминировать только один акцентный цвет.

### 5.3. Пространственная навигация

Приложение делится на три основных режима.

#### Atlas

Карта знаний, связи между темами и общий маршрут.

#### Focus

Текущий урок, повторение или практическая сессия.

#### Studio

Мини-кейсы, эксперименты и полноценные проекты.

Переходы между режимами должны ощущаться связанными.

Пример:

1. пользователь нажимает на узел `Random Forest` в Atlas;
2. узел плавно увеличивается;
3. связанные темы уходят на задний план;
4. открывается Focus-режим с уроком;
5. после урока интерфейс возвращается на карту;
6. состояние узла и маршрута обновляется.

Не должно создаваться ощущение, что пользователь каждый раз переходит в совершенно другое приложение.

### 5.4. Визуальные метафоры

Для интерфейса можно использовать несколько спокойных метафор:

- карта или атлас знаний;
- маршруты между темами;
- острова и области знаний;
- слои глубины;
- мягкое приближение к теме;
- постепенное заполнение маршрута;
- внешние кольца состояния вокруг узлов;
- лёгкие следы прогресса вместо ярких наград.

Главная визуальная идея:

> Не обычный граф из кружков, а спокойный интерактивный атлас знаний, который плавно превращается в маршрут курса, урок, кейс или проект.

## 6. Интерактивная карта знаний

Карта знаний — одна из центральных функций приложения.

Она не должна выглядеть как хаотичный `force-directed graph`.

Лучший вариант — представить знания как интерактивный атлас или архипелаг.

Крупные области знаний отображаются как отдельные территории:

```text
Python
SQL
Математика
Classic ML
Deep Learning
NLP
LLM и RAG
MLOps
```

При приближении внутри области появляются темы и подтемы.

Пример:

```text
Classic ML
├── постановка задачи
├── подготовка данных
├── линейные модели
├── деревья
│   ├── Decision Tree
│   ├── Random Forest
│   └── Gradient Boosting
├── метрики
├── кластеризация
└── снижение размерности
```

Связи между темами показываются как спокойные маршруты, а не как десятки пересекающихся линий.

Пример зависимости:

```text
Decision Tree
    ↓
Bias и Variance
    ↓
Random Forest
    ↓
Gradient Boosting
    ↓
CatBoost / LightGBM / XGBoost
```

### 6.1. Состояния темы

Каждый узел может находиться в одном из состояний:

- не изучено;
- доступно для изучения;
- изучается;
- теория понята;
- практика закреплена;
- знания начинают забываться;
- обнаружен пробел;
- требуется повторение.

Состояние лучше показывать сочетанием:

- заполнения узла;
- внешнего кольца;
- небольшой иконки;
- лёгкой анимации;
- изменения насыщенности маршрута.

Не использовать слишком много ярких цветов.

### 6.2. Информация о теме

При выборе узла открывается компактная карточка:

```text
Random Forest

Общее владение: 78%

Теория: 91%
Практика: 67%
Объяснение своими словами: 74%
Сохранность знаний: 81%

Последнее повторение: 8 дней назад

Следующий шаг:
решить мини-кейс по деревьям и ансамблям
```

### 6.3. Режимы карты

Карта должна поддерживать несколько представлений:

- весь атлас;
- мой текущий маршрут;
- слабые темы;
- темы для повторения;
- зависимости выбранной темы;
- знания для выбранной профессии;
- темы конкретного курса;
- темы конкретного проекта;
- темы, которые блокируют дальнейшее обучение.

## 7. Курсы как маршруты

Курсы не должны отображаться как обычные папки с главами.

Каждый курс — это маршрут по карте знаний.

Пример:

```text
Классическое машинное обучение

01. Постановка ML-задачи
        ↓
02. Подготовка данных
        ↓
03. Линейные модели
        ↓
04. Деревья решений
        ↓
05. Random Forest
        ↓
06. Gradient Boosting
        ↓
07. CatBoost, LightGBM и XGBoost
        ↓
08. Сравнение моделей
        ↓
09. Итоговый кейс
```

Маршрут может иметь ответвления:

```text
Классификация
├── кредитный скоринг
├── классификация текстов
└── прогноз оттока клиентов
```

Для каждого этапа показываются:

- краткое описание;
- ожидаемое время;
- связанные знания;
- тип практики;
- условия открытия;
- личный прогресс;
- рекомендуемое повторение;
- доступные мини-кейсы.

## 8. Формат уроков

Урок не должен выглядеть как длинная статья.

Он состоит из коротких интерактивных сцен. Пользователь движется по ним последовательно.

Пример урока по Decision Tree.

### Сцена 1. Интуиция

Небольшое объяснение на несколько абзацев с одной центральной визуализацией.

### Сцена 2. Интерактивный эксперимент

Пользователь двигает границу разделения и наблюдает:

- изменение Gini;
- количество объектов в узлах;
- глубину дерева;
- ошибку на train;
- ошибку на validation;
- появление переобучения.

### Сцена 3. Проверка понимания

```text
Что вероятнее всего произойдёт при сильном увеличении max_depth?

○ модель станет линейной;
○ модель может переобучиться;
○ масштабирование признаков станет обязательным.
```

После ошибки приложение показывает не только правильный ответ, но и причину ошибки.

### Сцена 4. Работа с кодом

```python
model = DecisionTreeClassifier(
    max_depth=___,
    min_samples_leaf=___
)
```

### Сцена 5. Объяснение своими словами

Пользователь отвечает:

> Почему глубокое дерево склонно к переобучению?

AI-наставник оценивает не стиль, а смысл ответа.

### Сцена 6. Вопрос с собеседования

```text
Почему дереву решений обычно не требуется масштабирование признаков?
```

### Сцена 7. Итог

```text
Теория: 86%
Практика: 72%
Объяснение: 81%

Рекомендуемое повторение: через 4 дня
```

## 9. Интерактивные форматы

Приложение должно использовать разные виды взаимодействия.

### 9.1. Визуальные эксперименты

Пользователь изменяет параметры и сразу видит результат:

- learning rate;
- глубина дерева;
- количество соседей в KNN;
- порог классификации;
- регуляризация;
- количество компонент PCA;
- размер batch;
- dropout;
- температура LLM;
- размер чанка в RAG;
- количество найденных документов.

### 9.2. Интерактивные графики

Например, при изменении threshold обновляются:

- confusion matrix;
- Precision;
- Recall;
- F1;
- количество ложных срабатываний;
- условная бизнес-стоимость ошибок.

### 9.3. Сборка последовательности

Пользователь располагает этапы ML-проекта в правильном порядке.

### 9.4. Соединение сущностей

Например:

- метрика и подходящая задача;
- модель и её свойства;
- ошибка и возможная причина;
- гиперпараметр и его влияние.

### 9.5. Поиск ошибки

Пользователь находит:

- data leakage;
- неправильный split;
- ошибку в pandas;
- неверную агрегацию;
- плохой выбор метрики;
- переобучение;
- неправильный способ оценки.

### 9.6. Карточки памяти

Карточки должны иметь разные форматы:

- вспомнить определение;
- объяснить своими словами;
- закончить формулу;
- выбрать график;
- найти ошибку в коде;
- сравнить два метода;
- ответить как на собеседовании;
- привести практический пример.

## 10. Практика и мини-кейсы

Практика должна строиться слоями.

```text
Упражнение по одной теме
        ↓
Мини-кейс по связанным темам
        ↓
Итоговый кейс по модулю
        ↓
Смешанный кейс по изученным направлениям
        ↓
Полноценный проект
```

### 10.1. Упражнение по одной теме

Проверяет отдельный навык:

- написать `groupby`;
- выбрать метрику;
- найти производную;
- объяснить regularization;
- исправить несколько строк кода.

Такие задания должны быть короткими.

### 10.2. Мини-кейс по связанным темам

Мини-кейс появляется после группы логически связанных уроков, а не после каждой темы.

Пример блока:

```text
Фильтрация данных
→ groupby
→ agg
→ merge
→ обработка пропусков
```

Мини-кейс:

> Есть таблицы клиентов и транзакций. Нужно посчитать количество и сумму операций за последние 30 дней, присоединить признаки к клиентам и правильно обработать клиентов без транзакций.

Другой пример:

```text
Дисбаланс классов
→ Precision и Recall
→ PR-AUC
→ Confusion Matrix
→ выбор threshold
```

Мини-кейс:

> Банк ищет мошеннические операции. Стоимость пропущенного мошенничества выше стоимости ручной проверки. Нужно выбрать метрику, подобрать порог и объяснить решение бизнесу.

Мини-кейс должен проверять небольшой полный цикл:

1. понимание задачи;
2. выбор подхода;
3. работу с данными или кодом;
4. анализ результата;
5. объяснение решения.

### 10.3. Итоговый кейс по модулю

После крупного блока пользователь получает задачу, объединяющую большую часть тем курса.

Пример после Classic ML:

> Построить модель прогнозирования оттока клиентов.

Необходимо выполнить:

```text
EDA
→ обработка данных
→ split
→ baseline
→ сравнение моделей
→ выбор метрики
→ подбор порога
→ анализ ошибок
→ интерпретация
```

### 10.4. Смешанные кейсы

В отдельном разделе находятся кейсы по всем уже изученным направлениям.

Примеры сочетаний:

```text
Python + pandas + SQL
Математика + ML + метрики
ML + бизнес-интерпретация
NLP + Transformers + оценка качества
LLM + RAG + backend
ML + API + Docker
```

Пример кейса «Скоринг клиентов»:

1. получить данные SQL-запросом;
2. построить признаки в pandas;
3. исключить утечку данных;
4. обучить несколько моделей;
5. выбрать метрику;
6. подобрать порог;
7. объяснить результат бизнесу.

Пример кейса «Локальный RAG»:

1. загрузить Markdown-документы;
2. разбить их на чанки;
3. получить embeddings;
4. настроить retrieval;
5. добавить reranking;
6. оценить ответы;
7. запустить систему локально;
8. объяснить ограничения решения.

### 10.5. Режимы сложности кейсов

#### Guided

Показываются этапы и доступны подробные подсказки.

#### Standard

Показывается задача и несколько контрольных точек.

#### Interview

Нет пошагового плана. AI-наставник играет роль интервьюера и задаёт уточняющие вопросы.

#### Real-world

В задаче присутствуют:

- неполные требования;
- лишние признаки;
- пропуски;
- дисбаланс;
- неоднозначная метрика;
- возможная утечка;
- ограничения по времени или ресурсам.

## 11. Персональная модель знаний

Приложение должно хранить не только факт прохождения урока, но и состояние знаний пользователя.

Для каждой темы оцениваются:

- понимание теории;
- способность применить тему;
- качество написания кода;
- интерпретация результатов;
- объяснение своими словами;
- ответы на собеседовании;
- количество подсказок;
- типичные ошибки;
- уверенность пользователя;
- дата последнего повторения;
- скорость забывания;
- связанные слабые темы;
- влияние темы на будущие разделы.

Пример:

```text
ROC-AUC

Теория: высокая
Расчёты: средние
Интерпретация: высокая
Практическое применение: низкое

Типичная ошибка:
ROC-AUC воспринимается как качество выбранного порога.

Рекомендация:
решить задачу с дисбалансом классов и самостоятельно подобрать threshold.
```

Важно разделять:

- узнавание правильного ответа;
- понимание;
- самостоятельное воспроизведение;
- применение в новой задаче;
- способность объяснить решение.

## 14. AI-наставник с RAG

AI-наставник не должен быть обычным чат-ботом в углу экрана.

Он должен учитывать:

- текущий урок;
- выбранный текст, формулу или код;
- материалы курса;
- прошлые ошибки;
- карту знаний;
- уровень пользователя;
- выполненные задания;
- текущий проект;
- цель обучения;
- результаты повторения;
- выбранный режим обучения.

### 14.1. Контекстные действия

Пользователь может выделить элемент и выбрать:

```text
Объяснить проще
Показать на примере
Объяснить математически
Сравнить с другим методом
Задать вопрос на понимание
Дать подсказку
Проверить моё объяснение
Добавить в повторение
```

### 14.2. Режимы наставника

#### Объяснение

Наставник адаптирует глубину ответа.

#### Сократический режим

Наставник не выдаёт готовый ответ, а задаёт наводящие вопросы.

#### Разбор ошибки

Наставник объясняет:

- где произошла ошибка;
- почему она появилась;
- с каким пробелом связана;
- что стоит повторить;
- какую задачу решить дальше.

#### Подготовка к собеседованию

Наставник:

- задаёт вопрос;
- оценивает ответ;
- задаёт уточнение;
- просит привести пример;
- проверяет понимание;
- сохраняет слабые места.

#### Проверка проекта

Наставник анализирует:

- постановку задачи;
- обработку данных;
- выбор метрики;
- архитектуру;
- качество кода;
- результаты;
- README;
- способность защитить решение.

## 17. Анимации и микровзаимодействия

Анимации должны помогать пониманию, а не просто украшать интерфейс.

Примеры:

- узел карты мягко раскрывается в экран урока;

- после завершения модуля маршрут постепенно заполняется;
- при изменении гиперпараметра график обновляется плавно;
- карточка повторения переворачивается без резкого эффекта;
- AI-объяснение раскрывается рядом с выбранным объектом.

Анимации должны быть короткими и спокойными, примерно 180–300 мс.

Следует поддержать режим уменьшенной анимации.

## Расположение учебного контента

Каноническое Obsidian-хранилище находится внутри репозитория по относительному пути `content/vault`.

- Папка content/vault является единственным источником учебных материалов для приложения и RAG.
- Требования:
* приложение должно использовать относительный путь content/vault;
* не использовать абсолютные пути конкретного компьютера;
* не создавать вторую копию учебных материалов;
* Markdown-файлы, Canvas, вложения и шаблоны должны сохранять исходную структуру;
* RAG должен индексировать только разрешённые материалы из этого хранилища;
* служебные файлы Obsidian не должны попадать в RAG-индекс;
* изменения учебного контента выполняются непосредственно в content/vault через Obsidian или редактор кода.



## 23. Итоговая продуктовая концепция

DataPath должен ощущаться не как набор страниц, а как единая обучающая среда.

Пользователь:

1. видит персональный план на сегодня;
2. переходит в интерактивный урок;
3. выполняет практику;
4. проходит мини-кейс по связанным темам;
5. получает обновлённую карту знаний;
6. повторяет слабые элементы;
7. возвращается к проекту;
8. получает помощь AI-наставника;
9. постепенно формирует устойчивые навыки.

Главная визуальная идея:

> Спокойный интерактивный атлас знаний, который плавно превращается в маршрут курса, урок, кейс или проект.

Главная продуктовая идея:

> Приложение не просто показывает материалы. Оно понимает состояние знаний пользователя и помогает выбрать следующий лучший шаг.
